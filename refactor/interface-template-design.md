## 核心概念

出卷系统由两个核心概念组成：**题型（Interface）**和**试卷模板（Template）**。两者独立存在，M:N 绑定。

| 概念 | 负责 | 谁维护 |
|------|------|--------|
| 题型（Interface） | 定义参数表单 + 持有 AI 提示词 + 调用 AI 产出数据 | 开发者调试好提示词，教师填参使用 |
| 试卷模板（Template） | 定义 Section 结构和参数槽位，声明各槽位的数据来源 | 开发者或教师均可创建 |

## 一、题型（Interface）

### 1.1 定义

题型代表一个具体的考试品类，比如"上海高考听说"或"中考听力"。它天然捆绑：

1. **题型结构信息**：该品类包含哪些 Section 类型（仅供 AI 理解上下文，不是实际的 Section 实例）
2. **教师输入参数**：全局配置，如难度、话题范围、题目数量等
3. **生成提示词**：描述这个品类如何出题、内容有什么要求、评分标准是什么

提示词强绑定题型。一套"上海高考听说"的 prompt 和一套"中考听力"的 prompt 本质上是两个不同的东西——题型结构不同、难度不同、评分标准不同——无法共用。提示词需要反复调试，所以按题型粒度划分，独立调优。

### 1.2 AI 生成

一次 Interface 调用 AI，产出一个完整的数据集——包含该品类下所有题型组的数据。比如上海高考听说 Interface 一次生成产出：

```
上海高考听说 Interface → AI 一次调用 →
  ├── 朗读句子组数据
  ├── 快速应答组数据
  ├── 情景问答组数据
  └── 看图说话组数据
```

### 1.3 数据实例

教师可以多次调用 AI，为同一个 Interface 生成多套数据实例：

```
上海高考听说 Interface
  ├── 实例 A（难度: 中等, 话题: 校园+科技）
  ├── 实例 B（难度: 困难, 话题: 环境+社会）
  └── 实例 C（难度: 简单, 话题: 日常社交）
```

实例保存在本地，可随时回顾、删除、重新生成。

## 二、试卷模板（Template）

### 2.1 定义

试卷模板定义了一份试卷的 Section 结构。每个 Section 有参数槽位。部分槽位绑定到 Interface（数据由 AI 填充），部分槽位不绑定（数据由教师手动填写）。

模板本身不生成数据，只声明数据来源。

### 2.2 Section 数据来源

模板中的每个 Section 可以标记为以下两种来源之一：

| 来源类型 | 含义 | 填写方式 |
|---------|------|---------|
| 绑定 Interface | 该 Section 的参数数据来自某个 Interface 的实例 | 从已生成的数据实例列表中选择 |
| 自定义 | 该 Section 的参数由教师手动填写 | 直接输入文本、上传文件等 |

## 三、M:N 绑定关系

### 3.1 部分消费

一个完整的 Interface 产出全部题型数据，但模板可以只取其中一部分。

```
上海高考听说 Interface（产出所有题型数据）
  ├── 朗读句子数据  ──→  朗读专项 Template（只取这部分）
  ├── 快速应答数据      （忽略）
  ├── 情景问答数据      （忽略）
  └── 看图说话数据      （忽略）
```

同一套 Interface → 多个不同模板，各取所需。全真模拟模板取全部，朗读专项模板只取朗读，快答专项模板只取快答。

### 3.2 多源拼装

一个模板可以从多个 Interface 取数据。

```
上海高考听力 Interface
  ├── 短对话  ──┐
  ├── 长对话  ──┤
  └── 短文    ──┤
                 ├──→  听说混合模板
上海高考口语 Interface  │
  ├── 朗读    ──┤
  ├── 快答    ──┤
  └── 看图    ──┘
```

听力 Interface 和口语 Interface 各有独立的提示词（分别调试），但可以拼进同一份模板。

## 四、教师完整工作流

### 阶段一：准备数据（Interface 管理界面）

1. 教师进入 Interface 管理页面
2. 选择一个题型（如"上海高考听说"）
3. 填写参数：难度、话题标签、题目数量等
4. 点击生成，AI 根据该题型的提示词产出数据
5. 可重复多次，生成多套实例（A、B、C…）
6. 实例保存在本地，可预览内容、删除不满意的、重新生成

### 阶段二：组装试卷（Template 编辑界面）

1. 教师打开一个试卷模板
2. 对于模板中每个 Section：
   - 如果 Section 绑定了 Interface → 从该 Interface 的已有实例列表中选择一套（选 A / 选 B / 选 C）
   - 如果 Section 是自定义类型 → 手动填写参数（输入文本、上传文件等）
3. 所有数据到位后，预览试卷
4. 完成 → 导出试卷

### 阶段三：最终调整（可选）

合成后的试卷仍可编辑。AI 生成的内容不是只读的——教师可以手动修改任何一句朗读文本、替换任何一张图片、调整任何计时参数。

## 五、与 Section 设计的关系

本文件描述的是"数据从哪来"的问题（Interface → Template）。[section-design.md](section-design.md) 描述的是"Section 如何组成试卷"的问题（from_child + 参数树 + 展开逻辑）。两者关系：

- **Section 引擎**：负责参数定义、嵌套、展开为题目序列
- **题型 / 试卷模板**：在 Section 引擎之上，负责出卷流程中的数据来源分工

一个 Section 组（比如"朗读句子组"）可以既作为 Interface 的产出目标（AI 生成文本内容），也可以作为 Template 中的自定义 Section（教师手动输入）。同一种 Section 类型不区分数据来源——数据只是填入参数槽位而已，来源是 Interface 还是手动填写对 Section 引擎来说是透明的。

## 六、术语对照

| 产品术语 | 技术概念 | 含义 |
|---------|---------|------|
| 题型 | Interface | 参数表单 + AI 提示词 + 题型结构信息。代表一个考试品类 |
| 试卷模板 | Template | Section 结构 + 参数槽位 + 数据来源声明。决定试卷长什么样 |
| 数据实例 | Instance | Interface 的一次 AI 生成结果。可保存、复用、删除 |
| Section | Section | 参数化的题目生成器。详见 section-design.md |
