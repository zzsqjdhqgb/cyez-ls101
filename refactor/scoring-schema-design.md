## 核心理念

批改端的设计与出卷端完全对称。出卷端有 Template + Interface 两层，批改端有 Schema + Schema 配置两层。

```
出卷端                                批改端
──────                                ──────
Template（定义 Section 结构）   ←→    Schema（定义评分项结构、配置格式）
Interface（填参, AI 生成内容）   ←→    Schema 配置（填提示词/参数）
试卷                             ←→    分数
```

评分 Schema 是一个**黑盒**：接受固定格式的配置 + 固定格式的录音数据，输出固定格式的分数。评分方式（人工还是 AI）对 Schema 的使用者透明。

## 一、评分 Schema 的结构

### 1.1 Schema 定义

一个 Schema 由若干**相互独立、互不关联**的评分项组成。每个评分项声明：

| 属性 | 说明 |
|------|------|
| 覆盖录音 | 对应哪些录音（来自 Template 产生的作答数据） |
| 评分维度 | 每维度的名称和满分 |
| 合并方式 | 多条录音是逐个评分还是合并评分 |

评分项之间没有顺序依赖、没有关联逻辑。每个评分项就是一个独立的打分任务。

### 1.2 配置格式

Schema 对外暴露一个配置格式——描述"这个 Schema 需要什么配置参数"。配置格式由 Schema 定义者声明。一个简单的例子：

```
Schema: 基础评分
  评分项:
    - item_0:  覆盖录音 [1,2,3], 合并评分, 维度 {发音, 流利, 语调}
    - item_1:  覆盖录音 [4], 独立评分, 维度 {内容, 语法, 流利}
  
  配置格式:
    { item_0: { prompt: string }, item_1: { prompt: string } }
```

配置格式是一个对象，由使用 Schema 的人来填充。填入不同的提示词 → 不同的 AI 批改行为。

### 1.3 合并评分

合并评分：多条录音视为一个整体评分项。教师（或 AI）一次性对全部录音打分。适用于朗读句子组（5 句话作为一个整体评估发音和流利度）。

独立评分：每条录音一个评分项。适用于快速应答（每个回答独立评估内容切题度）。

Schema 定义时声明每项的合并方式。

## 二、与 Template 的数据衔接

Template 展开为试卷后，产生 `gradingInfo`——每个评分项对应哪些录音。Schema 的评分项结构应该与 `gradingInfo` 的结构匹配。

```
Template 展开 → gradingInfo:
  - id: 0, 覆盖 [1,2,3], 合并, 维度 {发音, 流利}
  - id: 1, 覆盖 [4],   独立, 维度 {内容, 语法}

Schema 声明:
  - item_0: 期望覆盖录音 [1,2,3], 合并, 维度 {发音, 流利}
  - item_1: 期望覆盖录音 [4],   独立, 维度 {内容, 语法}

→ 匹配成功，Schema 可应用于该 Template 产生的作答
```

如果 Schema 的结构与 gradingInfo 不匹配（录音数量不对、维度不一致），系统提示无法应用该 Schema。

## 三、Schema 配置

### 3.1 配置实例

Schema 配置是配置格式的一个具体填充。不同配置实例产生不同的批改效果。

```
Schema: 基础评分
  配置格式: { item_0: { prompt: string }, item_1: { prompt: string } }

  ├── 配置实例 A（标准松紧度）
  │   item_0.prompt: "评估发音、流利度、语调。以中等标准计分，轻微错误不扣分..."
  │   item_1.prompt: "评估内容切题度、语法准确性、流利度。以中等标准计分..."
  │
  └── 配置实例 B（严格模式）
      item_0.prompt: "评估发音、流利度、语调。从严计分，任何发音偏差、停顿、语调异常均扣分..."
      item_1.prompt: "评估内容切题度、语法准确性、流利度。从严计分，语法错误零容忍..."
```

### 3.2 和 Interface 的对称关系

| 出卷端 | 批改端 |
|--------|--------|
| 题型（Interface）= 参数表单 + AI 生成提示词 | Schema 配置 = 按格式填提示词/参数 |
| Interface 可生成多套数据实例 | 同一 Schema 可有多套配置实例 |
| Interface 独立于 Template | Schema 配置独立于 Schema |
| Interface 可导入导出 | Schema 配置可导入导出 |

## 四、完整数据流

```
教师出卷:
  选 Interface → 填参 → AI 生成 → 数据实例
  选 Template → 绑定 Interface 实例 + 手动填写 → 合成试卷
  学生考试 → 产生作答（含录音）

教师批改:
  选评分 Schema → 选 Schema 配置 → 应用
  → Schema 黑盒接收: gradingInfo + 录音数据 + 配置
  → Schema 黑盒输出: 每个评分项的分数（人工打分或 AI 预填）
  → 教师核对/确认 → 结算 → 导出成绩
```

## 五、概念体系总览

```
Section 引擎
  ├── Section 类型定义
  │   ├── 参数 schema + 展开逻辑
  │   └── 默认评分结构（维度 + 满分 + 合并规则）
  │
  ├── 题型（Interface）          ← 出卷参数 + AI 生成提示词
  ├── 试卷模板（Template）        ← Section 结构 + 数据来源绑定
  │
  ├── 评分 Schema                ← 评分项结构 + 录音映射 + 配置格式
  └── Schema 配置                ← 填充 Schema 配置格式（提示词/参数）
```

出卷端 Template 对应批改端 Schema（结构定义者）。出卷端 Interface 对应批改端 Schema 配置（参数源）。两者完全对称。
