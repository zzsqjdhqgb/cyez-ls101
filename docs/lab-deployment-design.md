# 机房练习软件设计

状态：功能与架构设计，尚未实现。

本文件依据本轮讨论整理，是机房专用软件的设计依据。仓库中其他历史文档、重构草案以及主软件现有行为不自动构成本产品的要求；发生冲突时，以本文件明确记录的决定为准。本文中的程序名、文件扩展名和接口名称是设计名称，实际产品命名在实现时确定。

## 1. 产品范围

机房专用软件分为学生端和教师端两个桌面产品。教师端安装包内包含不依赖 Electron 的服务端程序。所有学生端依附所绑定的服务端运行。

首版只考虑学生自由选择试卷并完成练习，不建设正式考试、监考或严格终端控制系统。自由练习指自由选卷、自由开始和重复练习；播放器内部仍按试卷规定的时间线运行，不增加暂停、跳题、返回上一步或逐题练习。

保留和新增的核心能力：

- 学生端浏览服务端开放的试卷，完整下载并缓存后进行本地播放。
- 学生端收集作答，自动保存并尝试提交；管理提交异常与已提交历史。
- 教师端管理试卷、作答、设备、入网、维护与部署测试。
- 服务端提供认证、试卷分发、收卷、设备状态及有限的维护任务。

试卷制作与作答批改继续在主软件进行。机房软件沿用 `.lsexam` 和 `.lssubmission`，不包含模板编辑、内容生成、AI 服务、模型管理、评分、结算或成绩报告功能。

## 2. 安装形态与架构

### 2.1 两个安装包

只发布教师端和学生端安装包，不发布独立服务端安装包，不支持用户单独部署服务端，也不提供服务端管理 CLI。

教师端安装包包含服务端及其运行所需组件，无需用户另装 Node.js。服务端以独立后台进程运行，其业务代码不依赖 Electron；安装、后台托管、开机启动及卸载由教师端安装体系处理。

学生端安装包为无人值守安装设计，可由学校现有软件分发工具直接执行。教师端同样提供无人值守安装能力；无人值守安装不等于静默激活或静默信任未知服务。

本产品不采用系统镜像作为推荐部署流程，不建设镜像制作或数据克隆功能。

### 2.2 教师端每次启动选择连接

教师端完成激活与本机必要初始化后，每次启动显示服务连接页，可选择本机服务或任意已保存的远程服务，也可添加服务地址。可记住上次选项，但不因首次选择而固定为某一种工作方式。

连接页同时提供本机服务状态和启动、停止、开机启动设置、日志入口。这些操作不要求已经连接 HTTP 服务，但要求教师端已激活。连接远程服务时不会顺带启动本机服务。

连接后可以断开或切换服务。试卷、作答、设备和远程维护操作必须明确显示当前目标服务，本机进程操作始终明确标记为本机操作。

关闭教师端窗口或断开管理连接不停止已经启用的本机后台服务。服务端可随系统启动。首版不提供远程停止后台进程的接口；远程教师通过维护模式暂停学生业务，本机进程启停仍在服务所在机器处理。

### 2.3 沿用主软件的职责分配

桌面应用沿用主软件业务逻辑主要位于渲染进程的架构。教师端列表、筛选、页面状态、上传下载工作流，以及学生端页面、播放和提交工作流，主要由 renderer 组织。

Electron main/preload 负责必要的系统能力，例如单实例与启动参数接收、本地文件操作、协议注册、凭证保存、证书绑定以及本机后台进程管理。服务端负责自身的认证、授权、数据校验、持久化和状态权威判断，不能仅依赖 renderer 的按钮禁用来保护接口。

UI 不到处直接引用 Electron，只通过必要的窄接口访问平台能力。不为未来浏览器版提前建设完整的平台适配框架、浏览器部署方案或多套认证体系。将来需要浏览器管理时再补齐对应能力。

建议在当前仓库建立独立构建入口，复用播放器、共享类型、包编解码与适用的纯逻辑，不复制整套主软件再隐藏菜单。

## 3. 激活与状态优先级

### 3.1 激活优先

教师端和学生端首版使用激活码，后续与主软件统一升级到密码学激活，本次不提前设计或实现新的许可证体系。

未激活或激活已失效时，只允许激活流程和关闭软件，不允许连接、入网、浏览、练习、维护测试或数据导出。启动参数仍必须被正确接收和解析，但只执行激活命令，其他命令明确拒绝，不在激活成功后偷偷补执行。

服务端随教师端使用本机许可，不再要求单独激活。后台服务必须执行相同的许可有效性判断，不能因为教师 UI 关闭而绕过激活限制。未激活时，学生不会获得业务准入。

软件内限制不承诺对管理员权限用户提供操作系统层面的防绕过保护。

### 3.2 学生端准入顺序

按以下顺序决定正常业务准入，后面的状态不能绕过前面的限制。本节另行列出的激活命令、初次入网和临时失联后的本地导出是明确的有限例外：

1. 激活有效。
2. 本地初始化和数据升级成功。
3. 存在有效绑定，且能通过指纹校验连接到服务端。
4. 服务端许可有效，学生端与服务端运行版本完全一致。
5. 设备未被禁用，服务当前允许相应操作。
6. 根据维护模式、测试任务或正常模式显示对应页面。

未绑定但已激活的学生端可以接收入网命令。未激活不能先入网再激活。

版本不一致时，如果基础协议兼容，允许最小握手、查询状态和报告版本异常；服务端明确将设备标为异常，学生端显示不可用界面，只允许关闭软件。禁止练习、导出、重新上传、维护测试和入网变更。完全不兼容时拒绝连接并在学生端显示原因。更新安装由应用外部的安装程序完成。

激活命令的特殊处理仅用于未激活状态；已激活但版本不一致时，不通过其他命令绕过不可用限制。

正常练习开始后临时失联，不中断已开始的本地播放；这只是保护进行中的作答，不授予离线开始新练习的权限。版本升级应在维护流程中等待练习结束，不依赖运行中更换服务版本；意外发现版本不一致时不允许继续业务操作，已完成且已落盘的作答保留，不承诺恢复未完成时间线。

激活有效、无已知版本不一致且未处于维护锁定时，临时失联仍允许查看和手动导出本地异常作答与历史，便于处理无法上传的文件；不允许开始练习或执行远程操作。已经进入维护模式的设备不因断网解除维护锁定。

## 4. 教师端功能

| 页面 | 功能 |
| --- | --- |
| 连接页 | 每次启动选择服务、保存连接、添加地址、本机服务控制 |
| 试卷 | 上传、搜索、下载、删除、上架和下架 |
| 作答 | 按试卷、姓名、学号、机房和时间筛选，单个或批量下载、删除 |
| 设备 | 查看激活后已注册设备、座位、连接状态、版本、练习阶段、异常作答数量；修改设备标签、禁用、重置绑定 |
| 维护 | 模式切换、入网文件签发与撤销、部署测试、学生历史清理、升级前检查 |
| 服务设置 | 服务名称、监听配置、存储情况、管理密码、日志及备份入口 |

试卷上传后先校验，成功后默认上架。试卷内容不可原地编辑；同一包编号和同一归档摘要重复上传视为已存在，同一编号但不同内容拒绝覆盖。

下架停止新的分发和练习准入，不强行中断已经开始的练习。删除试卷不删除既有作答，也不拒收由该试卷已经产生的合法作答。

作答内容不可修改。批量下载时，外层 ZIP 内保留各个完整 `.lssubmission`。试卷删除、作答删除及批量清理均需明确确认范围。

首版设备管理不包含强制开考、强制交卷、屏幕监视、远程桌面或任意系统命令执行。

## 5. 服务身份、HTTPS 与权限

### 5.1 服务信任

局域网客户端与服务端使用 HTTPS。服务初始化生成稳定的 `serverId`、身份密钥和证书。专用客户端绑定服务身份与公钥 SHA-256 指纹，不以 IP 或主机名充当持久身份。

连接时先验证受信任公钥，再发送管理密码、入网凭据或设备令牌。绑定校验只作用于指定服务，不能全局忽略 TLS 错误，也不能跟随重定向把凭据发送到未绑定目标。

普通证书续期可保留公钥；意外公钥变化直接停止连接。合法密钥轮换必须由管理员通过既有信任关系或线下核对处理，本次不建设完整的自动证书轮换平台。

未来浏览器需要浏览器认可的 HTTPS 信任方式，不能在网页内直接复用 Electron 的证书校验策略；本次仅记录这一边界，不实现浏览器版本。

### 5.2 管理与学生权限

教师通过服务机器回环地址管理时免输管理密码；远程教师使用管理密码换取有期限的管理会话。本机判定依据实际连接来源，不相信请求内自报地址或未经信任的转发头。

本机免密不等于开放无保护管理接口。本机管理仍需本机签发的会话及来源约束，防止任意网页借回环地址执行删除操作。服务首次初始化通过本机管理能力完成。

学生端持有独立设备凭证，仅能获取允许的试卷、提交自身作答、查询自身回执、报告状态和领取授权给本设备的维护任务，不能读取其他设备作答或执行教师管理接口。

密码仅保存安全的校验结果；设备凭证和私钥按敏感配置保存。日志不得记录激活码、管理密码、入网令牌或完整设备凭证。

## 6. 入网文件与绑定

### 6.1 教师签发入网文件

教师在维护页开启入网等待并导出入网文件，默认有效期为签发后 10 分钟。开启入网等待自动进入维护模式。入网窗口关闭、过期或撤销后，不自动恢复正常练习，必须由教师明确退出维护模式。

入网文件至少包含：格式版本、用途、服务地址、`serverId`、服务公钥标识、入网批次 ID、签发时间、到期时间、随机入网凭据和密码学签名。只允许固定用途和受支持的算法；对完整有效载荷签名，采用标准签名封装和成熟密码库，不自定义签名算法。

服务端保存有效批次及撤销状态，按服务端时间检查有效期。客户端时间异常可提示，但不能依靠修改学生机时间延长入网窗口。文件有效不代表服务端永久开放入网。

一个批次文件可以在有效期内注册多台设备，适合无人值守分发。设备注册成功后取得自己的长期凭证，后续连接不再依赖文件是否过期。关闭批次不影响已经成功注册的设备。

### 6.2 防伪与首次信任的边界

签名必须对应可信服务身份。只验证文件自带公钥能够验证文件自己的签名，并不能阻止未知设备自建公钥伪造整份文件。

首次部署时，由管理员通过受控部署配置或启动参数提供从服务机核对过的公钥指纹。学生端以此校验入网文件签名和 HTTPS 对端身份；已经绑定的客户端可使用现有可信身份。不把文件内自报的指纹自动加入信任列表。

为了保持首版简单，入网签名使用与绑定服务身份相对应的密钥；签名格式与 TLS 证书格式可不同，但必须能核对到同一受信任公钥。具体支持的标准算法在实现时固定，不接受文件自行要求降级。

没有可信指纹时，文件不足以完成自动入网，必须由管理员先配置或核对信任。过期、签名错误、身份不匹配、批次撤销或服务不在入网等待状态，均拒绝注册并显示原因。

有效入网文件属于短期持有者凭据。密码学签名防止伪造和篡改，不阻止拿到真实文件的设备在有效期内申请注册。首版通过受控分发、短时窗口、撤销和教师设备核对控制这个范围，不增加硬件身份认证体系。

### 6.3 设备与学生身份

每台学生端首次注册生成独立设备身份，由服务端分配注册记录和设备凭证。IP、MAC、计算机名只作为辅助信息，不作为身份主键。教师可以设置机房、设备编号和座位名称。

设备绑定与学生作答身份分离。学生每次练习确认姓名和学号；首版无学生账户系统，不宣称这些信息经过实名验证。

一台学生端同时绑定一个服务。重复处理同一服务的入网请求应幂等，不创建重复设备。本产品面向固定机房，本地作答记录属于这台电脑；更换绑定保留全部旧记录，历史和异常列表统一展示，不按原服务拆分管理或清理权限。未确认提交结果的任务仍保留原服务身份，仅用于防止误投和确认原提交结果，不能静默把旧作答提交给新服务；后续只能向原服务确认回执或通过导出处理。

首版不提供换机迁移。更换电脑视为退役旧设备、重新安装和注册新设备，不复制设备身份、绑定或历史数据。

## 7. 学生端启动命令与单实例

### 7.1 命令用途

学生端支持由命令行调用图形应用，不提供交互式 CLI 界面。首版只支持激活与入网两类业务命令。示例名称如下：

```text
LabStudent.exe --activate <激活码>
LabStudent.exe "C:\Deployment\classroom.lsjoin"
LabStudent.exe "C:\Deployment\classroom.lsjoin" --server-fingerprint <管理员核对的公钥指纹>
```

入网文件作为位置参数，关联扩展名可由安装程序注册。安装程序提供稳定可定位的可执行文件路径；按部署需要注册应用路径或加入 PATH，不要求用户手工配置命令行环境。

激活和入网分为两次调用。未激活时即使同一调用带有入网参数，也不处理入网，不把它留待激活后执行。激活码不写入应用日志；部署工具须控制包含激活码的命令和分发记录的可见范围。

命令可以唤起界面，成功和失败均应有明确结果。仅有第二进程启动成功或退出成功，不能当作主实例已经激活或入网成功；部署结果以应用显示和服务端注册状态为准。

### 7.2 单实例处理

学生端必须单实例运行。首次启动参数、已有实例收到的 `second-instance` 参数以及系统文件打开事件进入同一个命令解析和调度路径。

已有实例运行时，新进程把结构化请求交给主实例后退出，不创建第二套窗口、播放器或后台上传器。窗口和业务尚未初始化时可以暂存请求，但执行时必须重新校验当前状态、文件时效及权限。

| 当前状态 | 命令处理 |
| --- | --- |
| 未激活或激活失效 | 只执行激活，拒绝入网和其他操作 |
| 已激活、未绑定或普通空闲 | 可在现有实例中处理合法入网请求 |
| 已激活、维护待机且版本一致 | 可处理合法部署命令，不开放普通学生操作 |
| 正在准备练习、正式作答、保存归档或运行部署测试 | 拒绝改变激活或绑定状态的命令，不中断当前流程 |
| 版本不一致或初始化失败 | 显示不可用原因，不执行业务命令 |

拒绝的命令不延期到练习结束后自动执行，管理员需要重新调用。已有普通上传任务时，不因异常列表非空而拒绝同服务幂等入网；涉及切换绑定则先完成或停止当前网络任务，保证作答目标不被替换。

启动参数是数据，不作为 shell 命令执行。文件路径按调用方工作目录规范化，拒绝未知参数、相互冲突的参数、超限文件和不支持格式。重复事件与并发命令需去重或串行处理。

## 8. 服务模式与学生端维护画面

### 8.1 模式由服务端决定

服务从首次初始化开始默认处于维护模式。模式持久化，服务重启保留维护状态；正常模式下的重启也不能跳过许可、版本或启动健康检查。

服务模式包括：

- 维护模式：禁止新练习，暂停正式作答上传，服务端不收取正式作答；可入网、核对设备、执行部署测试、清理历史和准备升级。
- 正常模式：允许符合条件的设备浏览和开始开放试卷，并处理正式作答提交。

入网等待与部署测试是维护模式内的活动，不作为学生自行切换的模式。进入入网等待先关闭新练习准入；已有练习可完成，部署测试只对空闲设备启动。开启入网等待不打断正在进行的测试，但应避免把仍在测试的设备重新绑定。

学生每次连接或重连取得服务模式、模式修订号、版本、设备权限和允许操作，之后通过心跳响应同步。服务端同时在业务接口校验当前模式，不能只依赖客户端保存的旧状态。

进入维护后，已有练习可以完成并可靠保存到本地，提交任务等待恢复正常模式；尚未开始的练习返回维护待机。维护期间不执行正式作答上传、重试或回执查询，也不增加教师代为重试或导出的入口。切换前已经持久化的收卷结果保留；在途请求未确认的结果留待正常模式核对。维护结束不会自动开始任何练习，提交任务按第 10 节的原状态继续处理。

授权部署测试只在独立测试空间验证上传和回执，是维护模式下的测试能力，不开放正式收卷。

### 8.2 维护待机画面

已激活、版本一致且已连接的学生端，在维护模式没有其他任务时显示全屏、不可操作的维护待机窗口，主要用于管理员在机房巡视核对。

画面包含放大的软件图标，以及清晰的服务名称、设备编号、计算机名、机房或座位、激活状态、客户端版本、连接状态和最近同步时间。布局必须让软件图标与设备编号从远处容易识别。

不提供试卷入口、设置、导出、重试或学生可点击的维护控制。操作系统级关闭不作强制拦截，不建设 kiosk 或防退出机制。

服务下发测试任务时切换到对应测试画面，结束后回到维护待机。失联、版本异常或激活失效时改为明确的异常或激活画面，不继续显示“已连接正常”的维护标识。未激活设备不会通过维护测试或入网绕过激活页。

## 9. 本地缓存与练习流程

### 9.1 本地资源访问

ExamPlayer 接受具有 HTTP GET 语义的根 URL，不要求真实 HTTP 服务器。当前代码的试卷入口通过内存 `fetcher` 提供这一语义；项目同时已有 Electron 自定义资源协议能力。

学生端完整下载 `.lsexam`，核对服务端提供的内容摘要，验证包结构、资源和安全路径，再以原子方式登记缓存完成。缓存按服务身份、包编号和归档摘要区分。

播放通过专用只读 Electron 协议或现有 `fetcher` 适配访问本地包，不启动本地 HTTP 服务器。协议仅暴露已验证的包资源，不开放任意文件访问。播放器继续独立于 Electron 和服务端协议。

缓存不完整、损坏或本地空间不足时不能开始。正在播放的缓存不得被清理；普通试卷缓存可以自动回收，但作答数据遵循独立的保留规则。

### 9.2 正常流程

1. 已激活学生端连接绑定服务，检查版本、模式和设备状态。
2. 展示服务端已上架试卷，提供搜索和缓存状态。
3. 学生选择试卷，完成本地缓存、播放器预检、姓名学号确认和必要的麦克风检查。
4. 在真正开始时间线前，向服务端取得绑定本次练习和试卷的短时开始许可。
5. 从本地执行完整时间线，采集选择答案和录音。
6. 完成后生成作答包，可靠落盘并登记提交任务。
7. 正常模式且准入条件满足时尝试上传，按结果进入历史或异常列表；学生可继续选择下一份试卷。若已进入维护模式，则保留本地提交任务并返回维护待机。

服务端无需访问互联网。学生机能 ping 通服务机并不足以证明可用，实际检查必须访问指定 HTTPS 端口并验证服务身份。

无法连接服务端时禁止开始，即使试卷已缓存也不能例外。进行中失联则继续本地播放，结束后保存为待处理作答；重新连接且准入条件满足后可开始新练习。

播放器不依赖服务端资源持续播放，不因心跳失败中断音频。试卷下架、服务进入维护或设备被禁用，不强制丢弃已经开始的作答。

首版不提供未完成练习的崩溃恢复。主动中途退出仍需确认，不产生完整作答包；完整作答可靠落盘以后，应用重启必须保留。

### 9.3 播放器需要的最小调整

缓存、服务连接、绑定、开始许可和上传由宿主处理。播放器可增加通用的开始前异步准入接口、身份确认与阶段通知，用于正式开始前检查服务，以及宿主状态上报；这些接口不得包含教师端、设备或 HTTP 管理协议类型。

当前播放器保存重试会重新生成作答编号。实现时须让一次练习使用固定作答编号，并在组包成功后复用同一份归档，避免重试制造新记录。

## 10. 作答保存、上传与历史

### 10.1 本地保存优先

播放器完成回调负责将完整作答包可靠保存到本地，并持久化提交任务。回调成功表示本地保存成功，不要求网络上传成功；界面必须区分本地已保存与服务端已收到。

本地保存失败不能显示完成，需保留可重试状态；网络上传失败只进入异常列表，不阻塞继续练习。服务断开、维护、版本不一致等独立准入限制仍有效，不能把“异常作答不阻塞”理解为允许离线练习。

后台上传按有限并发运行，不占用播放器流程，仅在正常模式且准入条件满足时处理正式提交任务。提交任务记录原服务身份，应用重启后恢复，不根据当前选择的服务改变目标；维护期间只保存本地任务。

### 10.2 作答状态

| 状态 | 含义 | 学生操作 |
| --- | --- | --- |
| 处理中 | 已落盘，等待首次上传、首次上传中或待核对回执 | 正常模式下查看，不阻塞符合准入条件的新练习 |
| 异常列表 | 上传失败、收卷结果待确认或需要人工处理 | 正常模式下选择并导出、重试上传；临时失联时按第 3 节允许本地导出 |
| 历史记录 | 服务端已持久化并返回成功回执 | 正常模式下选择并导出；临时失联时按第 3 节允许本地导出 |

学生端不提供任何作答删除、清空、历史重新上传功能，不自动按保留期清理作答。维护待机和版本不可用等更高优先级状态下，不开放这些列表操作。

首次上传自动进行。上传失败后不无限自动重传，放入异常列表；学生可在正常模式手动重试。重连、重启或退出维护后，只有正常模式且准入条件满足时，才自动核对尚未确认结果的已尝试提交，并继续尚未开始首次发送的持久任务。因维护暂停不等于上传失败，也不重置已有异常状态或触发失败任务自动重传。

已经开始上传但因维护中止的任务，持久化暂停原因和原状态。恢复正常模式且准入条件满足后，先查询原提交结果：已收取则持久化回执并归入历史；服务端明确确认未收取则自动重发同一作答编号的原归档；查询失败或结果仍不确定时保留待核对状态，不把无法查询当作未收取。自动重发发生普通上传失败时进入异常列表，后续由学生手动重试。维护前已经失败的任务仍保留异常状态，不因维护恢复而获得自动重传资格。

### 10.3 一次收卷与可靠重试

上传是一次性提交操作，学生端持久化成功回执即表示这次提交结束。之后教师删除服务端作答或恢复旧备份，都不触发历史重新上传、两端数据核对或补齐。本地历史用于留存和手动导出，不承担服务端备份恢复保障；下述查询与重试仅用于确认尚未结束的同一次提交。

超时不等于服务端没有收到。重试先按固定作答编号查询回执，再决定是否上传原文件。服务端对相同编号和摘要返回原回执，不重复建档；编号相同而内容不同则报冲突，不覆盖。

服务端只有在文件、索引和回执可靠持久化后才返回成功。学生端持久化回执后转入历史，不再允许上传；回执在传输或本地写入时丢失，可以通过查询恢复。

服务端删除作答仍保留最小收卷去重记录。客户端据此确认“曾成功收取，后由教师删除”，归入历史并显示事实，不把已删除作答重新上传。

服务端校验当前模式、包格式、大小、解压限制、安全路径、归档身份与当前上传设备权限。正常模式且准入条件满足时，已下架或已删除试卷的合法完整作答仍可收取；完成时间以包内时间保存，另记录服务端接收时间，不依赖学生机时钟进行去重或认证。

### 10.4 教师清理本地历史

首版提供教师发起的批量清理任务，可按机房、设备和截止日期选择范围，预览并确认。只清理有成功收卷回执的本地历史文件，绝不包含处理中、异常或未完成作答。

当前绑定服务的教师管理该设备的全部本地历史，包括换绑前留下的历史，不按原服务划分清理权限。清理依据本地已完成提交的状态，不要求再次确认服务端是否仍保存文件，也不承担恢复旧服务备份后的数据补救职责。

清理任务带唯一编号、目标设备、固定截止时间、有效期与任务状态。设备领取后在维护空闲时执行，回报实际清理数量及失败原因；重复领取不得重复产生副作用。教师可以查看在线成功、失败、离线待执行，并取消未执行任务。

不清理服务端作答，保留必要的本地收卷标记和服务端去重记录。过期任务不能在很久以后连接时继续删除新数据；学生无权限创建清理任务。

## 11. 状态通信与任务

所有通信由教师端或学生端主动连接服务端，不要求服务端能够主动访问学生机的监听端口，也不依赖局域网广播、组播或互联网服务。

首版建议学生每 5 秒心跳一次，20 秒未收到心跳标记离线。教师端以类似间隔刷新设备状态。服务端记录接收时间，显示最后已知状态，不把离线自动解释为退出或交卷完成。

心跳包含设备身份、客户端版本、激活状态、当前试卷、练习阶段、等待首次提交数量、提交结果未确认数量、异常作答数量和最近错误。维护期间完成并保存但尚未上传的作答计入等待首次提交，已尝试上传但尚未确认收卷结果的作答计入结果未确认。结果未确认的作答可能同时位于异常列表，各项分别展示，不直接相加作为作答总数。

教师端设备列表和维护检查显示这些数量，并以服务端接收本批统计的时间作为更新时间。设备离线或没有有效统计时明确显示最后已知值及时间或未知状态，不将未上报视为零。激活失效时不得继续业务会话，服务端保留最后一次已知激活状态及其时间，不声称已知离线设备的实时状态。

维护任务通过心跳或短轮询领取。首版任务限定为部署测试和历史清理，使用任务 ID、有效期、领取确认和结果回报。服务端不接受重复结果覆盖已完成任务，不把客户端上报的成功当作未经验证的收卷凭据。

HTTP 协议单独版本化，包含服务信息、认证、注册、模式、心跳、练习准入、试卷、作答回执和维护任务。基础协议兼容只允许诊断连接，不放宽学生端与服务端的软件版本一致要求。

## 12. 维护模式内的部署测试

### 12.1 定位与执行方式

从首次部署开始使用维护模式完成设备核对和测试。教师可选择一台、部分或全部设备，执行随软件安装的固定测试套件，查看逐台逐项结果，重试失败项并导出报告。

真实部署测试通过授权的维护任务在已经运行的学生端内执行，使用实际网络、本地存储、资源适配、播放器和录音能力。测试需要学生端已激活、已绑定、版本一致且空闲，不使用测试后门绕过这些条件。

测试代码只来自受信任安装包。远程任务只能选择内置用例与受限参数，不能下发任意 JavaScript、shell 命令或开启 Electron 远程调试。

### 12.2 与现有 Playwright 测试的关系

现有 Electron 集成测试会启动测试构建、创建临时用户目录并使用测试激活配置，不能原样应用到真实学生数据。当前不依赖将 Playwright 测试自动转换为真机测试套件的工具。

实施时复用适合共享的测试素材、包校验、结果断言及小型场景逻辑，分别由 CI 的 Playwright 测试和部署测试执行器调用。不把 Playwright、浏览器下载、临时测试许可或测试环境变量带入正式部署流程。

### 12.3 首版测试项

| 测试项 | 验证内容 |
| --- | --- |
| 身份与连接 | 服务指纹、设备凭证、版本、维护模式同步、心跳 |
| 存储 | 可写空间、临时写入与读取、归档校验、可靠保存路径 |
| 试卷下载 | 下载内置小型测试包，核对摘要、验证资源并登记测试缓存 |
| 本地播放 | 使用正式资源适配与 ExamPlayer 展示图像文字、执行短音频和选择题时间线 |
| 音频设备 | 枚举输入设备、检查权限、短时录音与回放、记录音频长度和信号情况 |
| 作答提交 | 生成测试作答，经正式编解码和上传流程获得回执，再由服务端校验 |
| 重复请求 | 对同一测试作答模拟回执重查和重复提交，验证只产生一条收卷结果 |
| 异常恢复 | 在测试范围模拟上传失败，确认本地保留、异常记录、手动重试路径和回执恢复 |

录音测试只在教师明确启动测试时短时运行并显示测试状态，不作为常驻监听。自动测试能验证设备调用和音频数据，不能证明耳机真正戴对、扬声器声音可听或麦克风位置正确；报告将这些列为需要现场确认的项目，不能自动标记全部通过。

自动测试结果区分通过、失败、取消、超时、离线和待人工确认，不把未执行当作通过。报告记录服务与学生版本、测试套件版本、设备 ID、时间、每项结果和具体错误。

测试包、录音和作答进入独立测试空间，经过相同核心处理流程但不混入正式试卷、异常列表或学生历史。只允许清理本次测试空间，测试清理不能成为学生删除正式作答的通道。

任务结束、取消或超时后释放麦克风等资源，学生端回到维护待机；断线导致的结果暂存并在重连时上报。离开维护前必须停止测试，不让迟到任务在正常练习中启动。

## 13. 首次部署流程

1. 在服务机无人值守安装教师端，启动并使用激活码激活。
2. 在当次连接页管理本机服务，初始化名称、端口、数据目录、管理密码、证书和开机启动；服务初始即为维护模式。
3. 配置固定地址或 DHCP 地址保留，允许实际 HTTPS 端口访问，核对服务指纹并记录受控部署配置。
4. 通过学校现有部署工具安装学生端，不使用系统镜像；安装完成后执行学生端激活命令。
5. 教师确认学生端已准备好后开启入网等待，导出默认 10 分钟有效的签名入网文件，避免在耗时安装前就消耗有效期。
6. 通过受控部署工具分发入网文件与可信指纹，调用图形程序处理入网。已运行的学生端在单实例内处理；未激活、忙碌或版本异常的设备明确失败。
7. 教师核对设备数量、名称和座位，巡视各设备全屏维护画面；不把只有软件图标但显示失联或异常的设备算作成功。
8. 对试点设备运行部署测试，再批量执行，处理失败项并完成声音等人工确认。
9. 关闭入网等待并撤销不用的批次；文件自然过期同样停止新注册。维护模式保持不变。
10. 上传正式试卷，在教师个人电脑验证远程管理。确认没有测试仍在运行且检查结果可接受后，由教师明确切换正常模式。

安装、激活、入网和测试分别记录结果，不能只依据安装程序退出成功推断系统部署成功。新增设备时重新开启一个短时入网批次，自动进入维护模式，重复相关检查。

如机房有重启还原软件，必须让设备身份、激活数据、绑定、历史和异常作答目录持久保存。软件本身不负责规避学校的磁盘还原策略。

## 14. 升级与维护流程

### 14.1 安装升级方式

首版不提供自动检查更新、下载更新、远程安装或自研软件分发系统。更新与首次安装一样，由管理员运行安装程序，复用既有数据；以后主软件加入更新能力时再统一引入。

安装目录与持久数据目录分离。正常覆盖安装保留激活、服务身份和证书、设备绑定、试卷、作答、历史、异常队列及收卷去重记录，一般无需重新激活或入网。

学生端与服务端分别负责自己数据的格式升级，失败时进入不可用状态，不悄悄重建为空数据。教师端本机服务与对应安装包一同升级。远程教师端至少检查管理协议兼容性；不兼容时拒绝管理，设备严格同版本规则专指学生端与服务端。

### 14.2 计划升级顺序

1. 教师进入维护模式，关闭入网等待，停止尚未执行的测试和清理任务，禁止新练习。
2. 等待进行中的练习结束并可靠保存到本地，维护期间暂停正式收卷。待提交和异常作答是维护检查项，不因其存在强制删除或阻止保护性升级；离线及尚未处理设备明确列出。
3. 短暂停止写入并完成一致性备份，包含数据、配置、身份密钥、凭证和回执；敏感备份受保护保存。
4. 在服务机运行新版教师端安装程序，升级配套服务及数据，检查服务恢复并保持维护模式。
5. 更新试点学生端，复用本地数据并执行必要升级；确认激活与绑定保留，通过部署测试。
6. 批量更新其他学生端。未更新设备即使能完成基础连接，也显示版本异常，学生界面只允许关闭。
7. 核对设备版本、连接、待提交和异常作答及测试结果，再明确退出维护模式。符合准入条件的设备按原状态继续处理提交任务，已失败的任务仍需手动重试。离线旧版本设备以后上线仍被版本规则拦截。

升级准备阶段必须等待活动练习结束，不在录音或归档保存过程中强制覆盖安装。数据升级失败时先保留原数据和诊断信息，不以重新激活、重新绑定或删除历史作为自动修复手段。

### 14.3 备份与恢复边界

备份用于故障恢复与升级失败处理，不包含跨机器迁移产品流程。需要回退时恢复相匹配的程序和数据快照，旧程序不得直接写入它不支持的新格式。

恢复旧服务备份可能缺少备份之后已收取的作答，这是恢复该快照的边界，不改变学生端已经完成提交的状态。软件不为此核对两端数据、重新上传历史或增加恢复协调流程。仍保留在学生机上的历史可按普通导出功能人工取用，但不保证可用于补齐服务端；历史清理规则保持不变。恢复界面明确备份时间和可能缺失的数据范围即可。

换机按新设备处理，不实施服务身份搬迁、学生身份复制或数据自动迁移。

## 15. 实现验收重点

- 两个安装包，服务只随教师端安装；教师端每次启动可重新选择连接目标。
- renderer 为桌面业务主要组织位置，播放器与 Electron、设备和远程服务契约解耦。
- 未激活只可激活或关闭；重复启动及启动参数不会产生第二实例或绕过限制。
- 首次信任来源明确；篡改、过期、撤销和未知签名入网文件无法注册。
- 初始维护、入网自动维护、模式重连同步和全屏待机画面符合约定；维护期间只完成并保存已有练习，不收取正式作答，恢复正常后按原状态处理提交任务。
- 因维护中止的在途上传，恢复后先核对回执，明确未收取才自动重发原归档；已有失败任务仍需手动重试，不能永久滞留于处理中或重复生成作答。
- 教师端能核对等待首次提交、结果未确认和异常作答数量及更新时间；维护期间尚未上传的作答可见，离线或未上报不显示为零。
- 学生端与服务端版本不一致时明确不可用，不能借协议兼容继续业务。
- 完整本地缓存后播放；服务不可达时不能开始，进行中临时断网不丢弃已完成归档。
- 上传失败进入异常列表且不阻塞正常条件下的新练习；成功回执持久化后提交结束，服务端删除或备份恢复不触发历史重新上传或两端核对。
- 换绑保留并统一展示本机旧记录；学生端没有删除作答能力，当前绑定服务的教师可按设备和日期清理本机已提交历史，不按原服务划分权限。
- 部署测试使用真实处理路径且隔离测试数据，不携带开发测试许可和远程任意执行入口。
- 覆盖安装保留数据、激活和绑定，数据升级失败不重置为空库。

后续实现修改 renderer、preload 或 main 时，按仓库要求运行 `xvfb-run -a yarn test:smoke`，并为新增行为运行对应 Electron 集成测试；跨模块最终验证运行完整集成套件。本文档本身不表示以上功能已经实现或测试通过。
