# 作答记录列表 · UI-SR-01

- 路由：`/submissions`
- 入口：一级导航「作答记录」；工作台快捷卡片「处理作答记录」与「查看作答记录」
- 对象：作答记录、评分结果、结算批次、评分报告

## 布局

单页标准布局，自上而下：

1. 页头：标题「作答记录」，右侧主操作「导入作答包」。
2. 一级标签页（`role="tablist"`，`aria-label="作答记录状态"`）：`未结算 <数量>`、`已结算 <数量>`。默认选中「未结算」；选中项由地址查询参数 `view` 决定（`view=settled` 为已结算，其余为未结算）。
3. 提示区：查询、导入、导出、删除或重新评分失败时显示带告警图标的错误条。
4. 内容区三态：加载提示、空状态或列表。

**未结算视图**：上方选择栏（`全选` 复选框、`已选择 <数量> 条`、主按钮 `开始评分（<数量>）`），下方表格，列为「选择」「作答人」「试卷」「作答时间」「评分进度」和无名操作列（列头 `aria-label="操作"`）。作答人列上行加粗姓名、下行考生号（以 `auto:` 开头时显示「考生号未填写」）。操作列依次为评分按钮、图标按钮「导出作答包」、危险图标按钮「删除作答记录」。评分按钮文案随进度变化：「开始评分」「继续评分」「进入结算」。

**已结算视图**：按结算批次分组的折叠列表，最新结算的批次在最上。批次头是展开按钮，含展开箭头、「结算于 <结算时间>」、「<数量> 条作答」和右侧「批次 <编号>」（编号按结算时间升序，最早的批次为 1）。展开后显示该批次表格，列为「作答人」「试卷」「分数」「作答时间」和无名操作列；操作依次为「查看报告」按钮、图标按钮「重新评分」「导出作答包」、危险图标按钮「删除作答记录」。分数列显示 `<总分>/<满分>`，无评分时显示 `-`。

携带查询参数 `batchId` 进入时，对应批次默认展开。

## 文案

- 页头标题：`作答记录`；主操作：`导入作答包` / 导入中 `正在导入`
- 标签页：`未结算`、`已结算`（各带数量）
- 加载中：`正在加载作答记录...`
- 未结算空状态：`没有未结算作答`
- 已结算空状态：`还没有已结算作答`
- 选择栏：`全选`、`已选择 <数量> 条`、`开始评分（<数量>）`
- 未结算表头：`作答人`、`试卷`、`作答时间`、`评分进度`、`操作`
- 评分进度：状态文字 `未评分`、`评分中`、`可结算`；副文案 `<已完成>/<总数> 个评分单元`，未评分时为 `尚未开始`
- 未结算行操作：`开始评分`、`继续评分`（部分完成）、`进入结算`（全部完成）、`导出作答包`、`删除作答记录`
- 已结算表头：`作答人`、`试卷`、`分数`、`作答时间`、`操作`
- 批次头：`结算于 <结算时间>`、`<数量> 条作答`、`批次 <编号>`
- 已结算行操作：`查看报告`、`重新评分`、`导出作答包`、`删除作答记录`
- 考生号空缺：`考生号未填写`
- 导入成功：`已导入 <姓名> 的作答包`；重复：`该作答包已经在作答记录中`
- 导出成功：`作答包已导出`
- 删除成功：`已删除 <姓名> 的作答记录`
- 重新评分成功：`已将 <姓名> 的作答移回未评分列表`
- 删除确认对话框：标题 `删除 <姓名> 的作答记录？`；正文按结算状态二选一——已结算 `删除后，原始作答包、评分结果和报告都会被移除。此操作无法撤销。`，未结算 `删除后，原始作答包和已有评分进度都会被移除。此操作无法撤销。`；确认按钮 `删除`
- 重新评分确认对话框：标题 `重新评分 <姓名> 的作答？`；正文 `现有评分、结算结果和报告将被删除，原始作答会作为未评分记录重新加入未结算列表。`；确认按钮 `删除评分并重新开始`
- 评分报告对话框：标题 `评分报告`；副标题 `<姓名> · <试卷>`；加载中 `正在生成报告...`；关闭按钮 `关闭报告`
- 导入与导出文件选择框：文件类型名 `LS101 作答包`（扩展名 `lssubmission`、`zip`）
- 错误文案按原因取以下之一：`无法导入作答包：<原因>`、`作答库中已有相同编号、但内容不同的作答包。`、`作答包不存在或已经被删除。`、`作答库数据损坏：<原因>`、`评分无效，请检查分数范围。`、`该评分单元已经提交，不能再次修改。`、`该作答已经完成全部评分单元，不能继续提交评分。`、`该作答尚未完成批改，暂时不能生成报告。`、`所选作答尚未完成全部评分，不能结算。`、`该作答尚未结算，暂时不能生成报告。`、`该作答已经结算。如需重新评分，请先删除现有评分记录。`、`结算数据已经发生变化，请重新加载后再试。`；其余错误显示原始错误信息，无信息时为 `操作失败，请重试。`

## 状态与恢复

- **加载中**：显示 `正在加载作答记录...`；两个视图都不渲染。
- **查询失败**：页头下方显示 `role="alert"` 错误条，列表不渲染，无页内重试入口。
- **空状态**：当前视图没有记录时显示对应空状态。
- **视图切换**：切换标签只切换展示并改写地址查询参数，不重新查询；两个标签的数量来自同一次查询结果。
- **勾选保持**：刷新列表后只保留仍然存在于未结算列表中的勾选；已结算或已删除记录的勾选被丢弃。
- **导出取消**：系统保存对话框被取消时不提示、不报错。
- **导出进行中**：任一导出发起后所有「导出作答包」按钮禁用，直到写入完成或失败。
- **报告加载**：打开报告对话框后显示 `正在生成报告...`，成功后渲染报告内容；失败显示错误条。关闭对话框后拒绝迟到的响应，不写回页面。
- **删除失败 / 重新评分失败**：错误写入页头提示区；对话框已关闭，列表保留原内容可再次操作。
- **重新评分成功**：列表刷新并把视图切回未结算。
- 页面在挂载时查询一次；导入、删除、重新评分成功后重新查询。

## 有损操作

- **删除作答记录**：不可逆，必须二次确认。未结算记录会移除原始作答包与已有评分进度；已结算记录还会移除评分结果与报告。确认文案已分别说明后果。
- **重新评分**：删除该作答已有的评分记录、结算结果和报告，保留原始作答包与作答人信息，记录回到未结算列表并显示为未评分。必须二次确认。若该作答属于多人结算批次，只从批次移除这一条；批次因此清空时删除空批次。首版不保留旧评分结果，也不提供撤销。

## 术语

`作答记录`、`作答包`、`评分结果`、`结算批次`、`评分报告`、`重新评分`，与 [`../glossary.md`](../glossary.md) 一致。界面不出现 `SubmissionLibraryRecord`、`SubmissionSettlementBatch` 等内部术语。

## 产物

- 导入产生作答记录，进入未结算列表。
- 行内或批量「开始评分 / 继续评分 / 进入结算」进入 [`UI-SR-02`](./UI-SR-02.md)。
- 「查看报告」在对话框内展示评分报告，不产生文件。
- 「导出作答包」产生一个 `.lssubmission` 文件。
- 删除后记录从列表消失；重新评分后记录回到未结算列表并显示为未评分。

## 锚点

```yaml
anchors:
  visual: VR-SR-01（tests/visual/submissions/UI-SR-01.spec.ts）
  visual-states: [default]
  behavior: SR-01…SR-05（tests/product-docs/modules/submission-records/）
```

`SR-01` 覆盖本页的连续导入与未结算列表（步骤 `import-submissions`）、批量勾选后启动评分（步骤 `grade-selection`）、下次结算后回到未结算并显示「可结算」（步骤 `defer-settlement`）、结算后切到已结算视图并展示批次（步骤 `settle-batch`），以及已结算记录的重新评分确认与回到未评分的路径（步骤 `restart-grading`）。
`SR-02`…`SR-05` 覆盖行内单条「开始评分 / 继续评分 / 进入结算」、已结算记录的评分报告对话框、导出作答包的取消与保存分支、以及删除未结算与已结算记录时的两种确认文案与取消/确认分支。已结算空状态与查询失败仍未覆盖。
