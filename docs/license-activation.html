候选方案说明 · 尚未确定最终方案

我们正在设计更合适的软件激活方式

目前没有长期联网激活服务器。我们希望在控制成本的同时，兼顾教师和学生的使用便利、设备更换、离线能力与个人隐私。

本文介绍的是候选方向，不是已经作出的决定，也不会在本页收集个人信息。

先了解使用场景

软件需要区分公共设备和个人设备。公共设备由学校统一管理，个人设备则主要是教师和学生自己的电脑。

公共设备：图书馆、机房等电脑可以直接采用硬件指纹绑定的许可证，由管理员统一收集设备信息、下发许可证。这部分主要属于学校管理流程，不是本次面向普通用户的重点征集内容。
个人设备：我们正在比较“绑定到设备的许可证”和“绑定到账号的许可证”两条路线。请重点结合自己的电脑使用习惯和可接受的操作流程来判断。

方向一：硬件 ID 绑定

软件根据当前电脑的硬件信息生成设备身份，许可证只对这台电脑有效。个人设备有三种可能的办理流程。

A1设备身份文件离线收集

不搭建服务器，用户和教师通过文件完成登记和发放。

  1. 软件在激活界面生成设备身份文件。
  2. 用户把文件提交给负责激活的教师或管理员。
  3. 管理员根据每个文件生成绑定到设备的许可证。
  4. 管理员把许可证发回用户，用户在软件中导入并激活。

可能的好处

  • 不需要持续运行服务器。
  • 适合网络受限的环境。
  • 设备绑定关系清晰。

需要考虑

  • 需要等待人工处理。
  • 管理员需要批量核对和发放。
  • 换机、重装和设备身份隐私需要规则。

A2临时服务器 + 手机扫码

每学期开学时临时开放激活网站，预计运行约一个月，目标成本控制在每次约 20 元以内。

  1. 用户在手机身份认证网站登录。
  2. 电脑软件生成设备身份二维码。
  3. 用户点击网站扫码按钮，扫描电脑上的二维码。
  4. 网站登记身份和设备，教师集中发放绑定许可证。
  5. 用户导入许可证完成激活。

可能的好处

  • 手机承担身份认证。
  • 比纯文件往返更容易登记对应关系。
  • 不必全年运行服务器。

需要考虑

  • 每学期需要部署临时服务。
  • 需要处理身份信息和二维码安全。
  • 许可证仍可能需要等待集中发放。

A3临时服务器 + 激活链接

用户使用教师发放的链接，在网页完成认证后由软件自动完成激活。

  1. 每学期开学时搭建临时激活服务器。
  2. 教师向用户发放激活链接。
  3. 用户在电脑软件中输入链接并点击激活。
  4. 软件打开网页，用户输入个人信息并登录。
  5. 认证通过后，软件自动取得激活结果。

可能的好处

  • 用户手动传文件较少。
  • 成功后可自动完成激活。
  • 登记和认证可以一次完成。

需要考虑

  • 需要设计链接和回调安全。
  • 依赖临时服务开放时间和网络。
  • 需要处理失败重试和过期链接。

方向二：账号绑定

许可证与个人系统账号关联，而不是固定绑定某台电脑。账号和密码需要专门生成，不能直接使用学籍号、身份证号等敏感信息。

B教师统一发放许可证和个人账号

  1. 每学期由教师统一下发一个许可证。
  2. 教师为每位用户单独生成系统账号和随机密码。
  3. 用户在软件中导入该学期许可证。
  4. 用户输入自己的账号密码完成激活。

可能的好处

  • 换机或重装时更灵活。
  • 不需要提交设备身份文件。
  • 可以按账号管理使用资格。

需要考虑

  • 需要账号生成、发送、找回和重置流程。
  • 要明确离线时如何验证有效性。
  • 需要限制账号共享和多设备使用规则。

方案 服务器 绑定对象 用户主要负担 换机灵活性 主要需要解决的问题

欢迎反馈这些问题

  1. 你是教师、学生，还是其他使用者？使用个人电脑还是学校公共电脑？
  2. 你更能接受提交设备身份文件，还是使用专门生成的系统账号？
  3. 每学期开学时用手机完成一次身份认证是否方便？
  4. 等待教师集中发放许可证是否可以接受？最长能接受多久？
  5. 你是否经常更换电脑、重装系统，或需要在多台电脑上使用？
  6. 首次激活或换机时没有网络，是否会造成实际困难？
  7. 如果使用账号方案，你最关心密码发送、找回、共享还是多设备限制？
  8. 你对临时网站收集哪些信息最敏感？完成认证最少需要哪些信息？
  9. 以上方案中你最愿意使用哪一种？请说明原因和不满意的地方。
