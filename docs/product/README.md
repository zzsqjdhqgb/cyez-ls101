# LS101 产品定义

本文档记录产品梳理过程中已经确认的产品事实和用户可见设计。它是后续界面设计、交互实现和 Playwright 集成测试的产品依据。

`design/`、`refactor/` 和旧版 README 中与本文档冲突的内容均视为历史草案，不作为当前产品行为的依据。

## 产品定位

LS101 是一套覆盖英语听说考试完整工作流的全能桌面工具。

产品不划分教师端和学生端，也不根据身份限制功能。用户可以在同一个应用中制作题型、设计评分单元和试卷模板、运行试卷、管理作答记录并完成评分。

## 工作台

工作台是应用首页，负责提供：

- 产品各项能力的快捷入口；
- 最近状态和重要信息的汇总。

工作台不拥有独占业务能力。工作台中出现的每个操作入口，都必须能够从对应功能模块独立进入和完成。

工作台不是教师或学生角色的门户，也不改变其他模块的权限或可见性。

## 一级模块

已确认的一级模块名称如下：

| 名称     | 定位                                           |
| -------- | ---------------------------------------------- |
| 工作台   | 应用首页、最近状态和快捷入口                   |
| 试卷库   | 管理已经生成并可以直接运行的试卷               |
| 作答记录 | 管理作答包、评分状态和结果报告                 |
| 题型库   | 管理可复用的题型定义及其题组内容               |
| 试卷模板 | 组织试卷结构、页面、题型、时间线和评分单元     |
| 评分单元 | 定义可复用的答案结构、评分输入、分值和评分标准 |
| 设置     | 管理应用配置、AI 能力和应用信息                |

已确认的一级导航顺序为：

1. 工作台
2. 试卷库
3. 作答记录
4. 题型库
5. 试卷模板
6. 评分单元
7. 设置

## 用户可见术语

- 用户界面统一使用“评分单元”，不向普通用户暴露 `Schema`。
- 用户界面统一使用“试卷模板”，与最终可运行的“试卷”区分。
- 用户界面使用“作答记录”，不使用带有特定角色倾向的“收卷”。
- `Interface`、`Schema`、`Template` 等名称可以继续作为代码和文件格式中的内部术语。

## 试卷模板生成试卷

“生成试卷”是从试卷模板创建可运行试卷的独立流程，使用全屏页面承载，不使用普通弹窗。生成页延续试卷模板编辑器的沉浸式工作区，占据整个窗口内容且不显示应用一级导航；用户只通过流程自身提供的返回或关闭操作离开。

生成流程在同一个全屏页面内依次呈现三个阶段：

1. **生成设置**：确认模板、题组、语音及其他生成参数；
2. **生成过程**：展示总体生成阶段和逐条音频合成任务；
3. **生成结果**：展示最终结果和后续操作。

进入页面不会自动开始任务。只有用户在“生成设置”阶段明确执行“开始生成”，流程才进入“生成过程”。

生成设置包含必填的“试卷名称”：

- 默认使用当前试卷模板名称；
- 用户可以在开始生成前修改；
- 生成后的试卷库条目名称使用该值；
- 导出文件的默认文件名使用该值。

用户从试卷模板编辑器进入生成流程时，如果模板存在未保存修改，系统先自动保存当前内容：

- 保存成功后进入全屏生成页；
- 保存失败时停留在模板编辑器并展示失败原因；
- 本次生成始终以完成保存的模板内容为依据。

首版生成任务仅在当前页面前台运行，不进入后台。生成过程中，用户执行返回或关闭操作时，页面必须先明确提示离开将取消本次生成：

- 用户确认离开时，取消当前生成任务并返回试卷模板编辑页；
- 用户选择继续生成时，保留当前任务和进度并停留在生成页面；
- 不允许导航操作无提示地中断生成。

音频合成任务按生成顺序执行。单条音频首次合成失败后，系统自动额外重试三次，即每条音频最多请求四次。达到上限仍未成功时：

- 立即中断整个生成流程，不再继续后续任务；
- 在当前进度和失败项目处展示错误；
- 提供手动重试操作；
- 保留本次任务中已经成功合成的音频；
- 手动重试时复用已完成结果，从失败项目继续，不从第一条音频重新合成。

用户主动关闭生成流程后，可以释放上述临时任务进度和音频结果。

生成过程固定展示以下总体阶段：

1. **准备试卷内容**：校验模板并读取所选题组；
2. **合成语音**：展示每条音频合成任务；
3. **整理试卷资源**：收集图片、已有音频等资源；
4. **打包试卷**：生成最终可运行的试卷包。

不包含语音合成动作的模板仍显示“合成语音”阶段，并将其标记为“无需处理”，以保持不同试卷生成过程的结构一致。

逐条语音合成进度复用产品现有的 `TaskProgress` 交互和状态模型：

- 每一条语音对应一个独立任务；
- 任务按实际合成顺序排列；
- 等待、执行、完成和错误信息由任务项自身呈现；
- 自动重试次数及最终失败原因记录在对应任务中；
- 不再为语音合成另外设计一套进度条或任务列表。

生成设置中的模板内容选择统一使用“题型”和“题组”表达：

- `Interface` 在用户界面中称为“题型”；
- `Interface Instance` 在用户界面中称为“题组”；
- 选择区域命名为“题组选择”；
- 每一项展示模板所需的题型名称，并从该题型已有的题组中选择本次内容；
- 不向用户显示 `Interface` 或“实例”等内部术语。

语音设置按用途分为“默认音色”“男声音色”和“女声音色”三组。三组均为必选，不提供回退或跟随默认音色的选项。每组分别提供以下三级联动选择：

1. 提供商；
2. 模型；
3. 音色。

不同用途可以分别选择不同的提供商、模型和音色；不要求三组使用同一个语音引擎。

如果模板完全不包含语音合成动作，生成设置不显示上述语音选择，也不要求配置语音。页面需要明确提示“此模板无需合成语音”，语音配置不得阻塞这类模板的生成。

生成页面需要：

- 展示生成过程中的全部步骤；
- 展示每一条音频合成任务的独立进度；
- 在生成完成后停留在结果页面，不自动导出文件，也不自动关闭；
- 提供相互独立的“加入试卷库”“导出文件”等后续操作；
- 只有用户主动执行关闭操作时，才结束并关闭生成流程。

结果页中的操作规则如下：

- “加入试卷库”是主操作，“导出文件”是次要操作，“关闭”是普通操作；
- “加入试卷库”成功后，按钮变为“已加入试卷库”并禁用，防止重复加入；
- “导出文件”可以重复执行，以便将文件导出到不同位置；
- 任一操作成功后都继续停留在结果页；
- 用户最终执行“关闭”后返回试卷模板编辑页。

生成成功后，如果结果既没有加入试卷库，也没有成功导出过文件，用户执行关闭时必须再次确认本次结果将被丢弃。只要已经成功完成任意一种保存操作，关闭时不再显示该提示。

## 测试即文档

后续确认的完整用户行为应首先实现为 Playwright 集成测试。

产品文档测试与其他自动化测试严格分离：

- `tests/product-docs/` 只覆盖已经确认的用户可见产品行为；
- `tests/integration/`、`tests/components/` 和 Vitest 继续覆盖技术回归、跨进程契约、组件状态和异常边界；
- `playwright.product-docs.config.ts` 使用独立的测试目录、运行产物和文档 reporter；
- 整套产品文档测试通过后，reporter 根据实际执行的用例、步骤、注解和截图生成 `docs/product/generated/`；
- 失败的产品文档测试不会覆盖上一次成功生成的文档。
- `docs/product/generated/` 是需要随代码提交和评审的产品文档，不加入 `.gitignore`；`test-results/`、trace 和 HTML report 等单次运行产物继续忽略。
- 完整的 `yarn test` 在技术回归测试通过后运行产品文档测试；`yarn test:product-docs` 仍可用于单独构建并验证产品文档。

- 测试从用户可以操作的界面进入，覆盖完整操作路径和可见结果。
- 测试名称和步骤应能直接表达产品行为，不依赖实现细节。
- 配套文档记录测试无法直接表达的前置条件、边界和明确不覆盖的行为。
- 新产品主线可以先建立一套独立的 Playwright 测试，再审查并删除旧测试中的重复覆盖。
- 在新测试稳定之前，不因表面重复提前删除旧测试。
