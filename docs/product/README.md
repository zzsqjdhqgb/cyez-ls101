# LS101 产品定义

本文档记录产品梳理过程中已经确认的产品事实和用户可见设计。它是后续界面设计、交互实现和 Playwright 集成测试的产品依据。

`design/`、`refactor/` 和旧版 README 中与本文档冲突的内容均视为历史草案，不作为当前产品行为的依据。

## 梳理原则

- 核心业务能力已经稳定，本轮以重新确认产品定位、用户流程和交互逻辑为主；
- `ExamPlayer` 的现有前端经过专门设计，应作为播放器体验基线，仅修改产品梳理中明确确认的差异；
- 其他模块的现有界面只代表当前实现和能力范围，不默认视为合理的产品设计；
- 其他模块需要根据已确认的产品逻辑重新检查信息结构、操作层级、反馈和常见用户习惯。

## 产品是什么

LS101 是一套覆盖英语听说考试“准备内容、制作试卷、运行考试、处理作答、评分结算”完整工作流的桌面工具。它把题目内容、评分规则、试卷结构、运行快照和作答结果拆成可以独立维护的对象，让同一套题型和评分标准可以反复制卷，也让已经产生的作答结果不受后续编辑影响。

产品不划分教师端和学生端，也不根据身份限制功能。用户可以在同一个应用中制作题型、设计评分单元和试卷模板、运行试卷、管理作答记录并完成评分。

## 产品解决什么问题

- 把“出什么题”和“如何给分”从一次性试卷中抽出来，形成可复用的题型、题组和评分单元。
- 把可编辑的试卷模板和可运行的试卷快照分开，避免模板修改影响已经发出的试卷。
- 把原始作答和评分结果分开保存，允许评分暂存、批量结算和指定记录重新评分。
- 为文字生成、图片生成、语音合成、语音识别和 AI 评分提供统一配置入口，但 AI 失败时不破坏已有内容或原始作答。

## 核心对象如何流转

一次完整工作不是从“模块”开始，而是从一个对象逐步产生下一个对象：

```text
评分单元 ──────────────┐
                       ├─> 试卷模板 ──生成──> 可运行试卷
题型定义 ──> 题组 ──────┘                         │
                                                  └─运行──> 作答包
                                                               │
                                                               └─导入──> 作答记录
                                                                            │
                                                                            └─评分──> 评分结果
                                                                                         │
                                                                                         └─结算──> 结算批次 / 报告
```

对象之间的关键约束：

- 评分单元定义答案结构、满分和评分标准；保存后作为稳定契约被模板引用。
- 题型定义规定字段和生成要求；题组是题型下可复用的具体内容。
- 试卷模板可以继续编辑；生成后的试卷是包含题目、资源和评分上下文的自包含快照。
- 作答包保存一次运行产生的原始身份、答案、录音和引用上下文；导入后成为作答记录。
- 评分只产生独立结果，不改写原始作答；结算把完成评分的记录归入批次，形成最终结果。

## 按工作顺序使用

从第一次使用开始，建议严格按[LS101 产品说明书](./guide/README.md)的章节顺序阅读：认识产品和对象链，准备评分标准与题型内容，制作模板并生成试卷，运行试卷保存作答包，最后导入作答记录并评分结算。

## 一级模块

已确认的一级模块名称如下：

| 名称     | 定位                                           |
| -------- | ---------------------------------------------- |
| 工作台   | 应用首页、最近状态和快捷入口                   |
| 试卷库   | 管理已经生成并可以直接运行的试卷               |
| 作答记录 | 管理作答包、评分状态和结果报告                 |
| 题型库   | 管理可复用的题型定义及其题组内容               |
| 试卷模板 | 组织试卷结构、页面、题型、时间线和评分单元     |
| 评分单元 | 定义可复用的答案结构、评分输入、分值和评分标准 |
| 设置     | 管理应用配置、AI 能力和应用信息                |

已确认的一级导航顺序为：

1. 工作台
2. 试卷库
3. 作答记录
4. 题型库
5. 试卷模板
6. 评分单元
7. 设置

## 用户可见术语

- 用户界面统一使用“评分单元”，不向普通用户暴露 `Schema`。
- 用户界面统一使用“试卷模板”，与最终可运行的“试卷”区分。
- 用户界面使用“作答记录”，不使用带有特定角色倾向的“收卷”。
- `Interface`、`Schema`、`Template` 等名称可以继续作为代码和文件格式中的内部术语。

## 文档分层

- `guide/` 是按用户任务顺序生成的产品说明书，回答“为什么做、先做什么、每一步看到什么、产出什么、下一步是什么”。
- `journeys/` 记录从明确起点连续产出并消费业务对象的标准用户旅程，不通过仓储预置旅程中的核心对象。
- `modules/` 和 `flows/` 是手写的产品设计约束，回答对象生命周期、边界和交互语义。
- 各归属目录下的 `behaviors/` 是成功执行后生成的详细操作页，提供与测试共同来源的用户动作、可见结果和界面截图。
- `coverage.md` 只做执行覆盖审计，不替代产品说明书。
