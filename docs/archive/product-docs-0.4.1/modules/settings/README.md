# 设置与 AI 能力

设置管理应用级偏好和 AI 能力。它是基础设施配置入口，不是题组或评分记录的工作区。

## 设置分区

- **外观**：主题和减少动态效果等应用偏好，修改后立即作用于当前窗口并持久化；
- **AI 引擎**：文字、图片和语音 Provider、模型、密钥和连接测试；
- **关于**：应用名称、版本和运行环境信息。

## Provider 生命周期

Provider 的配置生命周期统一为：

```text
新建草稿 -> 填写协议和地址 -> 测试连接 -> 保存配置 -> 发现 / 管理模型 -> 使用
                   \-> 测试失败：保留草稿，不写入配置
已保存 Provider -> 编辑 / 禁用模型 -> 删除并清理密钥
```

- 连接测试使用当前表单草稿，可以在不保存的情况下验证地址、协议和密钥；
- 保存后 Provider、模型和密钥分开管理，删除 Provider 必须同时清理对应密钥；
- 模型发现结果可以合并到草稿，用户仍需明确启用要使用的模型；
- 生成或评分任务开始后使用任务启动时确定的模型，不因设置页后续变化而中途切换；
- 手动图片 Provider 是无 API 配置时的后备入口，不代表图片一定由 AI 生成。

## 与主线的关系

只有真正影响当前任务的配置才在题组生成、试卷生成或 AI 评分的设置步骤中出现。Provider 管理本身不产生题组、试卷或评分结果；配置完成后回到对应业务工作区执行任务。

## 安全与失败

- API 密钥不在普通列表中明文展示；
- 测试失败、模型发现失败和任务取消都不得把半成品当成已保存配置；
- 任务失败应显示具体 Provider 和模型上下文，允许重试或更换配置；
- 删除 Provider 不影响已经保存的题组、试卷和作答记录，它们只保留当时生成结果。

## 待补充的自动证据

主线真正依赖的 Provider 配置、密钥替换、模型启停和失败恢复需要从技术 AI 测试中挑选少量用户路径，转化为 Playwright 产品文档行为。
