# 基于 hostname 的机房镜像部署

本设计替代其他机房文档中关于安装 UUID、本机加密设备身份和不支持镜像部署的规定。学校保证每台学生机的 hostname 稳定且唯一；hostname 去除首尾空白、统一小写后作为服务内唯一机器键。改名视为新机器。

## 客户端持久化边界

学生端在 `server-connection.json` 保存服务地址、serverId、公钥指纹和机房共享接入秘密，并可保留原服务连接用于旧作答回执核对。这些信息均不与特定计算机挂钩，可直接随系统镜像复制。

不得使用 Windows Credential API、DPAPI、Electron safeStorage、TPM 或用户/机器绑定的 secret-store 加密这些配置。采用普通 JSON 和限制文件访问权限；不将秘密交给 renderer，不记录日志。服务端只保存共享接入秘密的摘要。镜像及配置文件持有者可以接入该服务；hostname 是机器归属标识，不是硬件认证。

不再持久化 installationId、设备令牌、运行代次或设备配置。主进程从操作系统读取 hostname；设备 ID、设备凭据和运行代次从 HTTPS 握手取得，仅驻留内存。设备编号、机房、座位、显示名、禁用状态均以服务端为准。作答记录可保留原绑定快照以核对归属，但不得用快照恢复客户端身份。

作答、维护任务、临时传输及测试数据放在 hostname 对应的独立目录中。命令执行诊断也放在机器目录。镜像复制来的其他 hostname 数据不会被读取、自动上传或执行。服务连接配置不放入机器目录。

## 入网与启动

1. 管理员在母机导入短期签名入网文件并核对服务端公钥指纹。
2. `POST /enrollment/connections` 验证有效注册窗口，换取机房共享长期接入秘密。相同批次重复兑换返回同一秘密；关闭或过期只禁止新的兑换，不撤销已兑换配置。
3. 母机持久化服务连接配置，然后可制作镜像。每台机器启动时读取自己的 hostname。
4. `POST /student/sessions` 在校验共享接入秘密后，按 hostname 查找或创建设备，返回设备 ID、内存使用的设备秘密、绑定上下文及服务端分配的运行代次。首次自动创建也允许在正常模式进行，业务仍受许可、版本及设备禁用状态约束。
5. 相同 hostname 重装或恢复镜像取得原设备及教师配置。已有连接临时失联时沿用内存状态；进程重新启动但服务不可达时显示离线，不误显示为未入网，取得服务端状态前不开放练习或导出。普通断线重连不更换运行 ID；新进程使用新 UUID，由服务端递增运行代次。重复握手不重复递增；被新运行取代的旧运行不能重新夺回代次。

## 凭据、配置和任务

设备凭据由服务端密钥与凭据记录 ID 派生，只在客户端内存使用。同一设备重启保持凭据归属，以支持原作答上传和维护任务恢复。教师重置绑定撤销旧凭据并阻止普通自动连接；必须在有效入网窗口对该 hostname 再次入网，才能恢复访问。设备配置保留，旧作答仍遵循原绑定上下文仅核对或导出的规则。

绑定上下文由服务端凭据记录 ID 标识。切换服务保留原服务连接配置；使用原服务连接核对旧回执时不能把作答投递到当前服务。服务端在设备唯一约束及事务内完成机器创建、凭据选择和运行代次分配，避免并发注册重复设备。

## 验证与数据格式

项目尚未发布，不迁移旧 binding.json 或旧服务数据库；旧服务数据库明确拒绝打开；旧 binding.json 不参与身份恢复，客户端需重新导入服务连接配置。检查不同 hostname 共用镜像配置、相同 hostname 重装恢复座位、入网文件过期后连接、新运行取代旧运行、教师重置绑定、服务重启，以及不调用操作系统加密 API。

- 服务端测试：284 通过，7 跳过（其中包含平台条件限制）。
- 协议与镜像部署测试：49 通过，覆盖共享配置复制、hostname 配置恢复、服务端代次、并发握手、旧运行拒绝和重置绑定。
- 桌面宿主测试：16 通过；学生端状态与 UI 测试：41 通过；契约测试：3 通过。
- 独立打包服务端启动及收卷重启：2 通过。
- 默认 Electron smoke：12 通过；机房完整 Electron 集成：5 通过。
- lint、相关 TypeScript 项目检查、协议生成一致性检查通过。

未执行 Windows VM 或学校真机镜像验收。旧服务数据库需重新初始化，旧学生端需重新导入服务连接配置；不自动清除旧数据。
