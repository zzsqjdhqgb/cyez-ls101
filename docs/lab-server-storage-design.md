# 机房服务端存储与事务设计

状态：待审核的实现设计，尚未实现。范围依据[功能设计](./lab-deployment-design.md)与 [API 契约](./lab-server-api-design.md)。

## 1. 技术选择与所有权

首版使用本机 SQLite 数据库与独立归档文件。SQLite 启用外键、WAL 和 `synchronous=FULL`，写操作经单一服务进程的事务队列执行；不支持网络共享目录作为活动数据库或归档根目录，不运行多个服务进程共同写同一目录。进程启动必须取得数据目录独占锁。Node.js LTS 与 SQLite 驱动的具体版本在构建验证时固定，随教师端携带，不依赖系统已有 Node.js。

数据库负责身份、授权、资源索引、操作状态和去重事实；原始 `.lsexam`、`.lssubmission` 不存成数据库大字段。服务端代码只依赖 Node 与共享纯逻辑，不能引用 Electron。文件操作通过有限的存储接口执行，不将用户输入的文件名、包 ID 或路径直接拼接到数据目录。

```text
service-data/
  service.sqlite
  identity/                 # 私钥、TLS 证书；受服务账户权限保护
  incoming/<uploadId>.part  # 未提交文件，与归档处于同一卷
  archives/exams/<archiveId>.lsexam
  archives/submissions/<archiveId>.lssubmission
  test-data/<taskId>/
  backup-staging/<backupId>/
  backups/<backupId>.7z
  logs/
```

`archiveId`、`uploadId` 均由服务端生成。正式路径发布后不可原地覆盖；解压仅进入受控暂存目录，按现有包校验器检查安全路径、文件数量、大小、资源引用和媒体内容。目录及文件同步能力必须在目标 Windows 文件系统验证，不能把仅成功调用 `rename` 当作断电持久化保证。检测到同步失败时不签发成功回执。

## 2. 数据模型

下表为逻辑表，字段命名与 API 对齐；时间保存为 UTC 整数毫秒，接口转换 RFC 3339。版本、计数在 JSON 安全整数范围内。

| 表                                     | 关键字段与约束                                                                                                                          |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `service`                              | 单行；`serverId`、`mode`、`modeRevision`、`settingsRevision`、名称、对外地址、容量限制、schema 版本                                     |
| `security`                             | 单行；密码 KDF 算法、参数、盐、校验值、独立 `revision`；初始版本 1                                                                      |
| `teacher_sessions`                     | token 校验值唯一、签发时安全修订号、到期时间；密码更新后旧安全修订号全部无效                                                            |
| `enrollments`                          | ID、签发与到期时间、撤销时间、注册数；至多一个未关闭且未到期批次；保存受保护的签名文件供再次下载                                        |
| `devices`                              | ID 主键；`installationId` 唯一；编号唯一（包括禁用设备）；机房、座位、显示名、禁用状态、配置修订号、注册时间                            |
| `device_credentials`                   | 凭证内部 ID、设备 ID、秘密校验值、签发与撤销时间；每台设备至多一个有效凭证                                                              |
| `heartbeats`                           | 凭证 ID 主键；最大代次、运行 ID、最大序号、接受时间、诊断快照、统计更新时间；身份与排序记录不能按在线超时删除                           |
| `exams`                                | exam ID、包内 package ID、摘要、归档 ID、大小、标题、页数、资源数、上架状态、revision、导入和删除时间；package ID 在未删除试卷中唯一    |
| `practice_grants`                      | submission ID 主键；设备 ID、签发凭证 ID、exam ID、包 ID、试卷摘要、学生身份、grantedAt、startBefore；保留删除试卷后的必要元数据        |
| `uploads`                              | upload ID、种类、逻辑资源 ID、凭证或教师主体、声明摘要、暂存归档 ID、状态、创建时间；每个提交编号至多一个在途接收记录                   |
| `submissions`                          | submission ID 主键且关联准入；设备 ID、原归档摘要和大小、归档 ID、包内提交时间、接收时设备标签快照、receipt ID 唯一、接收时间、删除时间 |
| `tasks`                                | task ID、批次 ID、设备及签发凭证 ID、固定类型与参数、到期时间、状态、revision；设备至多一个有效执行租约                                 |
| `task_leases`                          | lease ID、task ID、runtime ID、签发与到期时间、取消状态；结果提交后不复用租约                                                           |
| `task_results`                         | task ID 与 lease ID 唯一；规范化结果摘要、完整结果、receivedAt、late；同租约不同结果冲突                                                |
| `test_runs` / `test_confirmations`     | 测试套件、固定目标设备、retryOf；每台设备的人工确认独立 revision，自动测试结果保持不变                                                  |
| `cleanup_plans` / `cleanup_selections` | 固定设备、截止日期、到期时间、计划 revision、设备预览摘要与统计、已确认范围；确认后不可扩大范围                                         |
| `idempotency`                          | 稳定主体、方法、规范路由、键联合唯一；请求摘要、资源 ID 或批量结果、保留截止时间                                                        |
| `file_gc`                              | 待物理删除的归档 ID、原因、重试时间；不承载业务删除事实                                                                                 |
| `backups`                              | ID、快照时间、schema 与发布版本、状态、加密文件摘要和大小、脱敏错误                                                                     |

设备主键决定作答归属，凭证 ID 决定当前授权和心跳排序。重置绑定事务撤销原凭证、取消旧凭证的未执行任务；同一安装重新入网保留设备 ID 和教师配置，生成新凭证记录。其他安装 ID 不能接管原设备。旧凭证仍返回 401，新凭证只能按同一设备归属访问记录；学生本地旧提交仍遵循换绑后仅核对或导出的规则。

教师作答列表默认按接收时的机房、设备编号快照筛选；设备 ID 筛选始终按稳定身份，详情同时展示接收时标签与设备当前标签，避免后来改座位重新解释历史。删除试卷后允许再次导入相同 package ID，分配新 exam ID；原准入仍指向原试卷记录。

## 3. 收卷提交与崩溃恢复

收卷成功的唯一提交点是数据库事务同时写入作答索引、回执并结束接收记录；该事务前原始归档必须已经持久化。网络接收、解压、摘要计算均不占用数据库长事务。

| 步骤                                                                                      | 持久化事实                              | 此处进程退出后的处理                                             |
| ----------------------------------------------------------------------------------------- | --------------------------------------- | ---------------------------------------------------------------- |
| 校验权限、准入、编号与大小，短事务占用逻辑提交编号                                        | `uploads=receiving`，生成独立 upload ID | 无收卷记录，启动恢复移除占用，允许以后查询 `not-received`        |
| 流式写暂存文件，核对真实摘要及包内容                                                      | 暂存文件可能不完整                      | 丢弃未提交暂存文件；不从半包猜测成功                             |
| 同步文件，关闭句柄，发布到唯一归档路径并同步目录                                          | 完整归档存在，仍未正式收取              | 没有数据库成功记录即不收卷；登记孤立文件清理，不在重启后补签回执 |
| `BEGIN IMMEDIATE` 后重新检查许可、版本、凭证、设备、模式及准入；写作答与回执，结束 upload | 一个事务提交全部业务事实                | 事务未提交则视为未收取；事务已提交则保留原回执                   |
| 返回 `201` 与原回执                                                                       | 收取事实已经完成                        | 响应丢失时查询或相同摘要重试返回同一回执                         |

模式检查必须读取此事务中的数据库值。事务检查失败时回滚，结束 upload 并将已发布文件登记清理；不删除同编号的既有成功文件。数据库提交报错且结果不确定时，先重新读取事务结果；仍无法确认则进入存储不可用，不能回答 `not-received`。

启动恢复在 readiness 为 `initializing` 时运行：取得目录锁、打开数据库并验证 schema、清理未提交 uploads、核对已提交记录与归档存在性、恢复垃圾回收与任务状态。成功记录缺失文件或摘要不一致是存储损坏，进入 `unavailable`，不得降级成未收取或要求重传。大文件全量摘要检查可在受影响归档首次读取前执行，读取验证期间不能发送该归档；启动至少核对所有引用文件存在及大小。

同编号已收取时先检查当前权限与声明摘要，相同摘要返回既有回执，不再次写文件；不同摘要返回冲突。已删除记录返回原回执与 `deleted`，不恢复文件。请求声明摘要不能授权覆盖既有内容。`receiving` 只表示本进程确实持有的接收或提交工作；接收设置有限超时，超时取消并清理，不能永久占位。

## 4. 并发操作的排序

| 操作对             | 一致性规则                                                                                    |
| ------------------ | --------------------------------------------------------------------------------------------- |
| 进入维护与收卷     | 共享 SQLite 写事务排序；维护先提交则收卷最终检查失败，收卷先提交则回执保留                    |
| 正常模式与任务领取 | 退出维护检查所有未终结测试/清理、有效租约及待建立/已建立的备份屏障；取消或到期前不能成功；领取也在写事务内重新检查模式和备份阻塞 |
| 入网创建与模式     | 同一事务写维护模式及批次；幂等回放不重新延长有效期，也不再次改变模式                          |
| 改号与其他配置修改 | 一个 revision CAS 和唯一编号约束；全部成功或全部回滚                                          |
| 密码修改与教师请求 | 密码 revision 更新是撤销点；所有管理写操作在提交时重新验证会话安全版本                        |
| 心跳与旧运行       | 按凭证主键比较代次和序号，同事务更新快照与接收时间                                            |
| 任务结果与取消     | 结果保留执行事实；取消/到期已先提交时标记 late，不把任务重新置为执行成功                      |
| 重置绑定与学生请求 | 最终提交再次检查凭证撤销状态；已经成功收取不回滚；任务旧凭证失去续租资格                      |

幂等主体采用设备 ID 或服务内单一教师管理主体，不使用短期教师 token。重新登录仍可查询同一幂等操作，但必须通过当前授权。普通请求有效载荷经 schema 验证后规范化计算摘要；密码与备份密码不存入通用幂等日志。备份密码的同键一致性使用服务端秘密密钥 HMAC 校验输入，结果仅用于比较，原密码只在任务内存持有；进程退出后该任务失败，需新键重新创建。

## 5. 导入、删除与下载

试卷导入使用与收卷相同的“文件先持久化，索引最后提交”顺序；同 package ID 同摘要返回现有记录，不同摘要冲突。删除试卷只软删除索引、撤销上架并登记文件清理，保留准入引用所需元数据。

删除作答先在数据库事务记录 `deletedAt`、保留最小回执及归属、登记 `file_gc`，再异步删除文件。接口成功表示该文件不能再被新下载访问，并不保证磁盘空间已经回收。清理失败记录错误并重试，不撤销删除事实。批量删除逐项提交，幂等记录保存每项结果；超时后相同键返回同一逻辑操作结果。

下载先在资源锁下检查索引并取得进程内只读文件引用，之后逻辑删除可完成，但物理清理等待已有引用释放。批量 ZIP 开始发送前按固定 ID 列表检查并取得全部引用，任一缺失都不发送成功头。断流不能生成“完整成功”的输出，教师端宿主仅在完成校验后发布目标文件。进程重启清空内存引用，再执行垃圾回收。

## 6. 备份与恢复

首版选择标准 7z AES-256 加密归档并加密文件名，调用随教师安装包固定版本的 7-Zip 引擎；具体集成必须支持从受控内存或私有 IPC 获取密码，不能将密码放入进程命令行或日志。此能力在安装技术验证中验收；本轮不下载或安装工具。

1. 维护模式下在受理事务中创建持久 `backup` 记录，并登记待建立的全局写入屏障（`pending` 即为阻塞状态）；事务同时确认没有执行中的测试、清理、有效租约或其他冲突任务。返回 202 后由服务内工作队列处理，密码仅留内存。`pending` 备份阻止新的冲突任务领取和退出维护。
2. 工作队列必须在同一原子状态转换中重新确认服务仍为维护模式、备份仍为 `pending` 且没有有效执行租约，再将其置为 `running` 并取得全局写入屏障；任一条件变化则将备份明确标为 `failed`，不得建立屏障。屏障等待已进入的短事务和归档发布完成，取消残留上传；新的冲突写入（包括心跳、会话与配置变更）返回 `SERVICE_NOT_READY` 和 `Retry-After`。公开状态与不冲突的只读下载可以继续。
3. 屏障内用 SQLite backup API 取得数据库快照，复制身份配置，并按快照清单复制不可变归档到 staging；禁止 GC 和新的归档发布。记录快照时间、每个文件摘要、schema 和 releaseVersion。不得直接拷贝运行中的主数据库文件而遗漏 WAL。
4. staging 完整且持久后释放屏障，保持维护模式；从固定 staging 加密，不把后来的变化加入快照。备份不包含其他备份、日志、临时上传或未完成加密文件。
5. 加密文件同步并验证可读取后，原子发布并将 backup 标为 ready；失败标为 failed。启动恢复将无工作进程的 pending/running 备份标记失败并释放屏障，不自动猜测密码重跑。

本机恢复必须停止服务，先完整校验密码、清单、摘要和程序/schema 兼容性，再在独立目录恢复。保留原目录，通过可恢复的目录切换记录安装已验证快照。恢复后撤销快照内教师会话、保持维护并完成初始化检查；学生已完成历史不核对、不补传。恢复可能回退设备配置 revision，客户端新连接必须重新建立配置基线，不能持久使用旧的 revision 高水位拦截恢复后的配置。

数据库快照中的 `backups` 记录只描述原目录的备份文件，这些文件不在备份清单中。恢复工具必须在独立恢复目录内，以一个事务清空全部 `backups` 记录（包括创建当前快照时的 pending/running 记录），并删除 `idempotency` 中方法为 POST、路由为 `/teacher/backups` 的备份创建记录；其他业务幂等及收卷去重记录保留。事务成功持久化后才能切换活动目录；失败则停止恢复，继续保留原目录。重复执行该准备步骤结果相同，不从旧记录重启备份任务。

恢复后的备份列表初始为空，旧 ID 的详情和下载返回 `NOT_FOUND`；新的备份从恢复后的活动目录重新创建并登记。原目录中的备份与用于本次恢复的归档保持原状，仍可由本机管理员保管或再次恢复，不自动扫描、复制或登记为新目录中的 ready 文件。这里清空的是恢复目录的索引，不是删除原备份文件。

## 7. 容量、保留与故障验收

初始建议每设备一个上传，全服务同时接收 8 个归档，单个 ZIP 导出最多 500 项；超过并发返回 429 和 Retry-After。上传前按声明大小预留容量，流式写入继续检查，保留至少 1 GiB 或数据卷 5% 中较大者的空闲空间。磁盘满或不可写返回存储错误，临时失败不能发布成功索引。

正式归档只由教师明确删除；成功回执、删除标记和相关准入不做时间淘汰。未收取准入首版保留。已终结维护任务、结果及对应幂等记录初始保留 90 天，测试媒体保留 7 天；有效执行或未终结清理不能因保留期被删除。已关闭入网秘密立即销毁，保留批次元数据；签名文件包含秘密，必须一起删除。备份由本机管理员管理保留，远程 API 首版不自动淘汰备份。

必须覆盖收卷表中每个崩溃点、成功响应丢失、维护与收卷并发、改号冲突、密码变更期间在途写入、GC 与导出并发、备份屏障中重启、缺失归档、磁盘满及同凭证心跳乱序。Windows 文件落盘、锁和服务账户权限单独验证。已有 `file-store` 的原子文件工具可作为实现参考，不将其进程内队列当作服务端数据库事务。

备份恢复专项：先创建备份 A，再创建包含 A 的 ready 索引及自身运行记录的备份 B，恢复 B 后确认备份列表为空、A/B 的旧 ID 查询和下载均为 404、备份创建幂等记录已清除，而原备份文件、正式回执及其他业务幂等记录保留。覆盖清理索引事务中及目录切换前崩溃后重新恢复，不能暴露缺失文件的 ready 索引。
