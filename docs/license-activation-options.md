# 软件激活方式候选方案

本文档记录当前没有长期联网激活服务器这一约束下，软件许可证的候选发放方式。它用于开问卷前整理背景和方案，不代表最终决定，也不构成当前版本的产品承诺。

## 讨论背景

- 当前暂不建设长期在线激活服务器，以控制运行和维护成本。
- 激活方案需要覆盖两类设备：公共设备和个人设备。
- 方案应尽量减少个人隐私信息的收集，避免把学籍号、身份证号等敏感标识直接当作账号或密码。
- 需要明确每学期的有效期、许可证发放责任、设备更换/重装后的处理方式，以及许可证丢失后的补发流程。

## 已确认的发放原则

- 只有账号绑定方案需要为每位学生分别生成和发送账号密码。
- 公共设备和四种硬件 ID 绑定方案都不需要逐人发送许可证。完成设备登记后，可以把所有设备的授权合并为批量许可文件，再将同一份文件统一发给所有用户。
- 软件只使用批量许可文件中与本机匹配的设备授权。批量发放许可文件不会公开用户个人信息，也不会因统一分发造成隐私泄露。
- “许可文件能否批量发放”与“身份认证网站如何保护个人信息”是两个不同问题。A3、A4 仍需单独规定认证信息的收集范围和保存方式。

## 公共设备：硬件指纹绑定许可证

公共设备包括学校图书馆、机房等由学校统一管理的电脑。

建议直接使用硬件指纹绑定的许可证激活：

1. 软件生成公共设备的设备身份信息。
2. 管理人员统一收集设备身份信息。
3. 根据设备身份生成绑定到具体电脑的授权，并合并为批量许可文件。
4. 将批量许可文件统一部署到公共设备并完成激活。

公共设备方案不作为本次面向普通用户的主要征集选项。需要另外确认的管理问题包括设备更换、批量部署、系统重装和许可证撤销。

## 个人设备的两条主要路线

个人设备包括教师和学生自己的电脑。当前有两条主要路线：

1. **硬件 ID 绑定**：许可证绑定到一台具体电脑。
2. **账号绑定**：许可证与个人账号关联，用户通过账号登录完成激活。

下面列出硬件 ID 绑定的四种流程，以及账号绑定的一种流程。

## 方案 A：硬件 ID 绑定

### A1. 设备身份文件离线收集

**流程**

1. 用户在软件激活界面生成设备身份文件。
2. 用户把设备身份文件提交给负责激活的教师或管理员。
3. 管理员根据收集到的设备身份生成对应授权，并合并为一份批量许可文件。
4. 管理员将同一份批量许可文件统一发给所有用户。
5. 用户在软件中导入文件，软件读取与本机匹配的授权并完成激活。

**优点**

- 不需要持续运行服务器。
- 可以完全通过文件传递，适合网络受限环境。
- 激活许可证可以明确绑定到单台设备。
- 许可证可以统一批量发放，不需要逐人核对收件人，也不会泄露个人信息。

**需要权衡的问题**

- 用户需要提交一次设备身份文件，并等待本批次授权生成。
- 管理员需要收集和处理设备身份文件，但生成后只需统一发放一份批量许可文件。
- 重装系统、更换硬件或换电脑后，原许可证是否失效以及如何补发需要明确。
- 设备身份文件包含哪些硬件信息、如何向用户说明，需要提前定义。

### A2. 批量收集设备身份二维码

**流程**

1. 用户在软件激活界面打开设备身份二维码。
2. 用户使用手机拍照或直接截取二维码图片。
3. 用户把图片发送给负责激活的教师或管理员；管理员不需要建立学生姓名与设备之间的对应关系。
4. 管理员批量识别收到的二维码，生成对应的设备授权，并合并为一份批量许可文件。
5. 管理员将同一份批量许可文件统一发给所有用户。
6. 用户在软件中导入文件，软件读取与本机匹配的授权并完成激活。

**优点**

- 学生只需要打开二维码、拍照并发送，操作难度较低。
- 用户不需要查找、保存或上传设备身份文件。
- 不需要搭建服务器，也不需要登记二维码属于哪一位学生。
- 许可证可以统一批量发放，不会通过许可文件泄露个人信息。

**需要权衡的问题**

- 照片模糊、反光、裁切不完整或屏幕摩尔纹可能导致二维码无法识别。
- 管理员需要批量整理、识别、去重，并确认是否存在遗漏或无效图片。
- 需要在软件中提供清晰、尺寸稳定且适合手机拍摄的二维码。

### A3. 临时激活服务器 + 手机扫码登记

**流程**

1. 每学期开学时临时搭建激活服务器，预计只运行约一个月；目标成本控制在每次约 20 元以内。
2. 用户在手机上打开身份认证网站，输入个人信息并登录。
3. 用户在电脑软件中生成设备身份二维码。
4. 用户点击网站上的扫码按钮，使用手机扫描电脑上的二维码。
5. 网站完成身份与设备的登记。
6. 教师将登记设备的授权合并为批量许可文件，并统一发给所有用户。
7. 用户在软件中导入文件，软件读取与本机匹配的授权并完成激活。

**优点**

- 比纯文件往返更容易建立“用户—设备”的对应关系。
- 手机端可以承担身份认证和扫码操作，电脑端不必输入过多个人信息。
- 服务器只在每学期开学阶段运行，长期成本可控。
- 许可证可以批量统一发放，不需要逐人发送，也不会通过许可文件泄露个人信息。

**需要权衡的问题**

- 每学期都需要部署、维护和关闭临时服务器。
- 身份认证网站需要处理个人信息，必须明确收集范围、保存时间、访问权限和删除方式。
- 教师仍需要等待一批设备完成登记后生成批量许可，激活可能不是即时完成。
- 需要考虑二维码被转发、重复使用、过期和冒用的防护。

### A4. 临时激活服务器 + 激活链接

**流程**

1. 每学期开学时搭建临时激活服务器。
2. 教师向用户发放一个激活链接。
3. 用户在电脑软件中输入激活链接并点击激活。
4. 软件打开网页，用户在网页中输入个人信息并登录。
5. 网站完成身份认证后，软件自动取得本机对应的激活结果。

**优点**

- 用户操作步骤较少，成功后可以自动完成软件激活。
- 不需要用户手动下载、导入许可证文件。
- 身份认证和设备登记可以在一次流程中完成。
- 不需要为每位用户单独生成账号密码或逐人发送许可文件。

**需要权衡的问题**

- 需要每学期部署临时服务器，并保证激活期间可访问。
- 需要设计安全的链接、临时凭据和回调机制，防止链接泄露、重放或被冒用。
- 网页仍然需要处理个人信息，隐私和数据保留规则必须清楚。
- 浏览器与桌面软件之间的跳转、网络中断和激活失败后的重试需要有明确体验。
- 如果用户错过服务器开放期，可能需要人工补发或离线兜底流程。

## 方案 B：账号绑定的激活

**流程**

1. 每学期由教师统一下发一份公共许可证。
2. 教师为每位学生单独生成并发送系统账号和密码。
3. 用户在软件中导入该学期许可证。
4. 用户输入自己的系统账号和密码。
5. 软件在本地完成账号与许可证的匹配，完成激活。

账号不直接使用学籍号、身份证号等现实身份标识；应使用专门生成的、与敏感身份信息脱钩的系统账号和随机密码。

这是所有候选方案中唯一需要向每位学生分别发送个人凭据的方案。公共许可证仍可统一发放，只有账号和密码需要逐人发送。

**优点**

- 许可证不必绑定某一台电脑，用户更换或重装设备时更灵活。
- 教师可以按账号管理个人使用资格，理论上更容易处理补发和撤销。
- 用户不需要提交设备身份文件，也不需要手动完成设备登记。

**需要权衡的问题**

- 账号和密码的生成、发送、找回、重置和停用都需要管理流程。
- 如果激活完全离线，软件如何验证账号是否仍有效、如何避免账号共享，需要明确设计。
- 账号密码本身成为需要保护的凭据，不能复用学校已有的敏感身份标识。
- 一个许可证是否允许多个设备使用、同时登录和换机次数需要明确限制。
- 如果未来需要在线校验，仍可能引入服务器成本；如果不在线校验，撤销和防共享能力会受到限制。

## 候选方案对照

| 方案              | 是否需要服务器 | 绑定对象        | 发放方式                   | 用户操作负担 | 换机灵活性 | 主要风险                       |
| ----------------- | -------------- | --------------- | -------------------------- | ------------ | ---------- | ------------------------------ |
| 公共设备硬件指纹  | 否             | 单台公共电脑    | 批量许可文件统一部署       | 低           | 低         | 批量部署、重装和设备更换       |
| A1 文件离线收集   | 否             | 单台个人电脑    | 批量许可文件统一发放       | 中           | 低         | 设备文件收集、等待批次生成     |
| A2 二维码照片收集 | 否             | 单台个人电脑    | 批量许可文件统一发放       | 低           | 低         | 图片质量、批量识别和遗漏       |
| A3 临时服务器扫码 | 每学期约一个月 | 单台个人电脑    | 批量许可文件统一发放       | 中           | 低         | 临时服务、认证数据、二维码冒用 |
| A4 临时服务器链接 | 每学期约一个月 | 单台个人电脑    | 自动激活，无需逐人发放     | 低到中       | 低         | 链接安全、回调失败、服务窗口   |
| B 账号绑定        | 当前设想可离线 | 个人账号/许可证 | 公共许可统一发，账号需逐人 | 中           | 高         | 账号共享、凭据管理、离线有效性 |

表格中的“低/中/高”只是当前讨论用的相对判断，后续应结合实际用户数量、教师工作量和隐私要求重新评估。

## 问卷建议关注的问题

1. 你是教师、学生，还是其他使用者？使用的是个人电脑还是学校公共电脑？
2. 你更能接受提交设备身份文件，还是使用个人系统账号？
3. 在软件中打开设备二维码、拍照并发给管理员，是否比提交设备身份文件更方便？
4. 每学期开学时通过手机完成一次身份认证是否方便？
5. 等待教师生成并统一发放一批许可证是否可以接受？可接受的等待时间是多少？
6. 你是否经常更换电脑、重装系统或在多台电脑上使用？
7. 对于账号方案，你能否接受使用一组专门生成、与学籍号和身份证号无关的账号密码？
8. 你对临时激活网站收集哪些信息最敏感？哪些信息是完成身份认证所必需的？
9. 在没有网络时，首次激活或换机激活是否是刚性需求？
10. 哪些失败场景最需要人工帮助：忘记密码、许可证丢失、硬件变化、错过开放期，还是其他情况？
11. 在以下方案中，你最愿意使用哪一种？为什么？

## 当前阶段的边界

- 当前软件中的硬编码邀请码只是过渡实现，不代表上述方案已经选定。
- 本文档不规定最终的服务器、账号、许可证文件格式或硬件指纹算法。
- 在确定方案前，应先征集用户对便利性、隐私、换机和离线能力的优先级。
