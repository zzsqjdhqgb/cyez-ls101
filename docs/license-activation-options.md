# 软件激活方式候选方案

本文档记录当前没有长期联网激活服务器这一约束下，软件许可证的候选发放方式。它用于开问卷前整理背景和方案，不代表最终决定，也不构成当前版本的产品承诺。

## 讨论背景

- 当前暂不建设长期在线激活服务器，以控制运行和维护成本。
- 激活方案需要覆盖两类设备：公共设备和个人设备。
- 方案应尽量减少个人隐私信息的收集，避免把学籍号、身份证号等敏感标识直接当作账号或密码。
- 需要明确每学期的有效期、许可证发放责任、设备更换/重装后的处理方式，以及许可证丢失后的补发流程。

## 公共设备：硬件指纹绑定许可证

公共设备包括学校图书馆、机房等由学校统一管理的电脑。

建议直接使用硬件指纹绑定的许可证激活：

1. 软件生成公共设备的设备身份信息。
2. 管理人员统一收集设备身份信息。
3. 根据设备身份下发绑定到具体电脑的许可证。
4. 在公共设备上导入许可证并完成激活。

公共设备方案不作为本次面向普通用户的主要征集选项。需要另外确认的管理问题包括设备更换、批量部署、系统重装和许可证撤销。

## 个人设备的两条主要路线

个人设备包括教师和学生自己的电脑。当前有两条主要路线：

1. **硬件 ID 绑定**：许可证绑定到一台具体电脑。
2. **账号绑定**：许可证与个人账号关联，用户通过账号登录完成激活。

下面列出硬件 ID 绑定的三种流程，以及账号绑定的一种流程。

## 方案 A：硬件 ID 绑定

### A1. 设备身份文件离线收集

**流程**

1. 用户在软件激活界面生成设备身份文件。
2. 用户把设备身份文件提交给负责激活的教师或管理员。
3. 管理员根据每个设备身份文件生成绑定到该设备的许可证。
4. 管理员把许可证发回用户。
5. 用户在软件中导入许可证完成激活。

**优点**

- 不需要持续运行服务器。
- 可以完全通过文件传递，适合网络受限环境。
- 激活许可证可以明确绑定到单台设备。

**需要权衡的问题**

- 用户需要经历“提交文件—等待—接收许可证”的往返流程。
- 管理员需要人工处理、核对和批量下发文件。
- 重装系统、更换硬件或换电脑后，原许可证是否失效以及如何补发需要明确。
- 设备身份文件包含哪些信息、是否可能暴露设备或用户隐私，需要提前定义。

### A2. 临时激活服务器 + 手机扫码登记

**流程**

1. 每学期开学时临时搭建激活服务器，预计只运行约一个月；目标成本控制在每次约 20 元以内。
2. 用户在手机上打开身份认证网站，输入个人信息并登录。
3. 用户在电脑软件中生成设备身份二维码。
4. 用户点击网站上的扫码按钮，使用手机扫描电脑上的二维码。
5. 网站完成身份与设备的登记。
6. 教师在需要时集中下发绑定到设备的许可证。
7. 用户在软件中导入许可证完成激活。

**优点**

- 比纯文件往返更容易建立“用户—设备”的对应关系。
- 手机端可以承担身份认证和扫码操作，电脑端不必输入过多个人信息。
- 服务器只在每学期开学阶段运行，长期成本可控。

**需要权衡的问题**

- 每学期都需要部署、维护和关闭临时服务器。
- 身份认证网站需要处理个人信息，必须明确收集范围、保存时间、访问权限和删除方式。
- 教师仍需要集中生成或发放许可证，激活可能不是即时完成。
- 需要考虑二维码被转发、重复使用、过期和冒用的防护。

### A3. 临时激活服务器 + 激活链接

**流程**

1. 每学期开学时搭建临时激活服务器。
2. 教师向用户发放一个激活链接。
3. 用户在电脑软件中输入激活链接并点击激活。
4. 软件打开网页，用户在网页中输入个人信息并登录。
5. 网站完成身份认证后，软件自动取得本机对应的激活结果。

**优点**

- 用户操作步骤较少，成功后可以自动完成软件激活。
- 不需要用户手动下载、导入许可证文件。
- 身份认证和设备登记可以在一次流程中完成。

**需要权衡的问题**

- 需要每学期部署临时服务器，并保证激活期间可访问。
- 需要设计安全的链接、临时凭据和回调机制，防止链接泄露、重放或被冒用。
- 网页仍然需要处理个人信息，隐私和数据保留规则必须清楚。
- 浏览器与桌面软件之间的跳转、网络中断和激活失败后的重试需要有明确体验。
- 如果用户错过服务器开放期，可能需要人工补发或离线兜底流程。

## 方案 B：账号绑定的激活

**流程**

1. 每学期由教师统一下发一个许可证。
2. 教师为每位学生单独生成并发送系统账号和密码。
3. 用户在软件中导入该学期许可证。
4. 用户输入自己的系统账号和密码。
5. 软件在本地完成账号与许可证的匹配，完成激活。

账号不直接使用学籍号、身份证号等现实身份标识；应使用专门生成的、与敏感身份信息脱钩的系统账号和随机密码。

**优点**

- 许可证不必绑定某一台电脑，用户更换或重装设备时更灵活。
- 教师可以按账号管理个人使用资格，理论上更容易处理补发和撤销。
- 用户不需要提交设备身份文件，也不需要手动完成设备登记。

**需要权衡的问题**

- 账号和密码的生成、发送、找回、重置和停用都需要管理流程。
- 如果激活完全离线，软件如何验证账号是否仍有效、如何避免账号共享，需要明确设计。
- 账号密码本身成为需要保护的凭据，不能复用学校已有的敏感身份标识。
- 一个许可证是否允许多个设备使用、同时登录和换机次数需要明确限制。
- 如果未来需要在线校验，仍可能引入服务器成本；如果不在线校验，撤销和防共享能力会受到限制。

## 候选方案对照

| 方案              | 是否需要服务器 | 绑定对象        | 用户操作负担 | 管理员操作负担 | 换机灵活性 | 主要风险                         |
| ----------------- | -------------- | --------------- | ------------ | -------------- | ---------- | -------------------------------- |
| 公共设备硬件指纹  | 否             | 单台公共电脑    | 低           | 中到高         | 低         | 批量部署、重装和设备更换         |
| A1 文件离线收集   | 否             | 单台个人电脑    | 中到高       | 高             | 低         | 往返等待、人工处理、设备身份隐私 |
| A2 临时服务器扫码 | 每学期约一个月 | 单台个人电脑    | 中           | 中             | 低         | 临时服务、身份数据、二维码冒用   |
| A3 临时服务器链接 | 每学期约一个月 | 单台个人电脑    | 低到中       | 中             | 低         | 链接安全、回调失败、服务窗口     |
| B 账号绑定        | 当前设想可离线 | 个人账号/许可证 | 中           | 中             | 高         | 账号共享、凭据管理、离线有效性   |

表格中的“低/中/高”只是当前讨论用的相对判断，后续应结合实际用户数量、教师工作量和隐私要求重新评估。

## 问卷建议关注的问题

1. 你是教师、学生，还是其他使用者？使用的是个人电脑还是学校公共电脑？
2. 你更能接受提交设备身份文件，还是使用个人系统账号？
3. 每学期开学时通过手机完成一次身份认证是否方便？
4. 等待教师集中发放许可证是否可以接受？可接受的等待时间是多少？
5. 你是否经常更换电脑、重装系统或在多台电脑上使用？
6. 对于账号方案，你能否接受使用一组专门生成、与学籍号和身份证号无关的账号密码？
7. 你对临时激活网站收集哪些信息最敏感？哪些信息是完成身份认证所必需的？
8. 在没有网络时，首次激活或换机激活是否是刚性需求？
9. 哪些失败场景最需要人工帮助：忘记密码、许可证丢失、硬件变化、错过开放期，还是其他情况？
10. 在以下方案中，你最愿意使用哪一种？为什么？

## 当前阶段的边界

- 当前软件中的硬编码邀请码只是过渡实现，不代表上述方案已经选定。
- 本文档不规定最终的服务器、账号、许可证文件格式或硬件指纹算法。
- 在确定方案前，应先征集用户对便利性、隐私、换机和离线能力的优先级。
