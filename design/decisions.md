# 设计决策碎片

本文档记录在设计讨论中达成的具体策略。不等同于定稿设计文档，仅存放碎片化的决策信息。

## Interface 的唯一性策略

### ID 方案

- 用户创建的 Interface：UUID v4（随机生成），保证跨设备全局唯一
- 内置预设 Interface：UUID v5（基于固定 namespace + 名称哈希），保证跨设备展开出相同 UUID，且与用户 ID 永无交集
- InterfaceDef.id 是 UUID 字符串，不可变
- InterfaceDef.name 用于 UI 显示，不参与唯一性逻辑

### 两区隔离：草稿区 + 成品区

| | 草稿区 | 成品区 |
|---|---|---|
| 编辑 | 自由编辑、复制、重命名 | 不可编辑、不可重命名 |
| 删除 | 直接删除，无后果 | 删除前警告并列出引用此 Interface 的所有 Template |
| 导入 | 不可导入 | 从文件导入，导入后即为成品 |
| 导出 | 可导出为文件分享 | 可导出为文件分享 |
| 可见性 | 仅 Interface 编辑器可见 | Template 编辑器的变量选择器可见 |
| 内置 Interface | 不适用 | 存放在此处 |

**流转**：用户在草稿区调好 Interface → 点击"发布" → 复制到成品区（新 UUID）→ 草稿版保留不删，可继续迭代。

**更新已发布内容**：不属于直接编辑。路径是：草稿区改 → 再发布 → 获得新 UUID → 用户手动去 Template 里切换引用。不自动迁移，不隐式断链。

**实现**：在存储层标记 status: "draft" | "published"，或分两个目录存储。
