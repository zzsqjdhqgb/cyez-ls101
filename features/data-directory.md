# 数据目录

## 功能状态

应用将业务数据统一写入可配置的 `dataRoot`。默认位置是 `app.getPath('userData')/data`；Electron Cache 和 GPUCache 仍位于 Electron `userData`，不会随业务数据迁移。

固定位置的 `userData/data-location.json` 是启动引导配置，记录格式版本、当前业务数据目录和挂起迁移。每个有效业务数据目录包含 `.ls101-data.json` 标记。主进程在注册 File Store、Config Store 和 AI Router 前解析或迁移目录。

## 设置与迁移

“设置 → 存储”显示当前目录和占用空间。用户可以选择空目录并复制当前数据，直接使用另一个带有效标记的数据目录，或将默认业务数据目录作为候选位置恢复。恢复默认位置与手动选择目录经过相同的候选检查、重复/嵌套检查和迁移确认流程。普通非空目录、文件系统根目录、挂载点、源目标互相嵌套和数据目录内容中的符号链接会被拒绝；目录本身会解析为真实路径后再检查包含关系。根目录或挂载点中应先新建一个专用空目录，以保证迁移可以原子提交。

复制请求先原子写入带迁移 ID 的 `migrating` 引导状态，再重启应用。每次迁移使用目标旁由迁移 ID 唯一确定的暂存目录；新进程在任何业务存储注册前复制源目录，按相对路径和文件大小校验，并在暂存目录标记事务完成。

提交时只允许删除仍为空的目标目录，再把已校验的暂存目录原子重命名为目标。如果复制期间有其他程序向目标写入内容，迁移会停止并原样保留这些内容。进程在复制、删除空目标、重命名或写入 `ready` 状态之间退出时，下次启动会清理未完成的自有暂存目录、复用已完成的暂存目录，或识别已带相同迁移 ID 的目标并直接提交 `ready`。源目录始终保留。

迁移或切换已有数据目录成功后，`ready` 引导状态会记录迁移前的旧数据目录，“设置 → 存储”提供永久删除操作。在旧目录清理完成前不能再次更改位置，因此新目标不会与未清理旧目录重复或互相嵌套。主进程只接受删除引导状态中记录的目录，不接受 renderer 传入任意路径；删除前核对目录 UUID、父目录文件系统身份以及与当前目录的包含关系。删除事务先把旧目录原子重命名到带 UUID 的隐藏删除路径并持久化接管身份，再递归清理，进程退出后可继续且不会误删同名替代目录。

应用使用单实例锁，避免两个进程同时迁移或写业务数据。自定义目录在启动时不可访问时，主进程提供重试、选择已有受管理目录或退出三种恢复操作。选择原目录或其他已有目录以放弃挂起迁移时，主进程会尝试删除该事务的自有暂存副本；如果外接卷或网络卷暂时不可访问，`ready` 引导状态会保留已有的待清理和旧目录记录，后续启动继续重试。待清理记录保存暂存父目录的文件系统身份；父目录身份匹配但暂存目录已经不存在时可安全销账，目录重新出现时还需核对迁移身份，不能直接删除同名目录。只有实际看到、验证并成功删除暂存目录，或确认同一父目录中暂存目录已不存在后，待清理记录才会移除。

## 旧数据整理

没有引导配置和数据目录标记，但 Electron `userData` 根目录存在已知业务目录时，应用执行一次旧数据整理。只复制 `config`、`secrets`、`models`、`extensions`、`template-editor`、`interfaces`、`schema-editor`、`exam-library` 和 `submission-library`；Electron 缓存不复制。原目录内容会保留。

## 进程边界

renderer 只通过 `window.dataDirectory` 获取目录信息、调用系统目录选择器、请求默认目录候选以及提交迁移或使用已有目录。路径检查、文件复制、引导配置和重启全部由 main 负责。preload 暴露固定的数据目录 IPC 方法，不向 renderer 提供 Node.js 文件系统能力。

## 验证覆盖

文件系统测试覆盖全新初始化、旧数据筛选整理、挂起复制的各个崩溃恢复点、目标目录并发写入保护、旧目录删除身份校验、再次迁移限制和非空目录拒绝。主进程测试覆盖数据目录错误与其他启动错误的恢复边界。renderer 测试覆盖空目录迁移、使用已有数据目录和旧目录删除确认。Electron 集成测试覆盖真实进程重启后的目录切换、源数据保留及随后删除。
