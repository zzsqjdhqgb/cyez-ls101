## 1. 现有研究

现有方案大致可以分为三类：一类是训练专用的语音评测大模型；一类是先提取音素、再用 GOP 对比打分；还有一类同样先提取音素，但不做 GOP，而是让大语言模型直接判断。需要说明的是，公开研究在横向对比时常用 SpeechOcean762、MultiPA 等数据集，但它们主要是"和别人比"的标尺，不是本课题的主要评估依据；本课题更关注在真实教学录音和自建题型上的可用性。下面分别说明这三类方案，以及它们共同依赖的音素提取环节。

### 1.1 路线一：训练专用语音评测模型或语音大模型

这类方案用大量标注数据训练一个专用评分模型（或语音大模型），输入录音、直接输出分数。它的优点是流程短、上限高，但有两个现实问题。一是贵：需要大量人工标注和算力，训练成本高，做成服务后调用价格也不低。二是泛化性不足：这里的泛化性主要是指对录音设备的适应能力——换一套麦克风、换一个录音环境，准确度就可能明显波动。对学校场景来说，学生用的手机、耳机、机房麦克风五花八门，这是很难回避的技术限制，不是靠调一调提示词就能解决的。像 MultiPA 这样的多任务监督模型、以及部分商用发音评估服务，都属于这一类。

### 1.2 共同前置：先把语音拆成音素

除了上面这类端到端方案，其余方案都有一个共同前提：先把语音拆成音素。音素是构成每个发音音节的最小声音单位，可以理解为"这个音节里具体发了哪些音"。只有先知道学生实际发了哪些音素，才能进一步判断每个音发得准不准。因此，音素提取（也叫音素识别或强制对齐）是后面两类方案的共同基础。

### 1.3 路线二：GOP——逐音素对比再综合打分

GOP（Goodness of Pronunciation，发音优度）的思路是：针对每一个音素，用特定的对比算法衡量"学生实际发的音"和"标准音"有多接近，得到一个音素级的准确度；再把音素、单词、句子的分数逐级综合，得到整句评分。这条路线的好处是可解释：能指出具体是哪个词、哪个音出了问题，工程上也相对成熟。但它很依赖音素识别和对齐的质量，阈值需要针对口音、设备做校准；阈值定得不合适，就容易把连读、弱读、口音等正常现象误报成"读错"。

### 1.4 路线三：LLM 直接判断

第三条路线不做 GOP 的逐步对比，而是把转写、音素或音频等材料直接交给大语言模型，让模型自己判断。TextPA（EMNLP 2025）是这一类的代表：它不训练评分模型，而是先做转写和音素描述，再让大模型输出准确度、流利度和理由。此后出现的 Finetuned SpeechLLM、Prior over Evidence、TTS-PRISM 三篇工作也都属于 LLM 直接结合的思路：有的把评分细化到句子、单词、音素三个层级，有的专门分析大模型反馈的可靠性，有的把类似思路用于语音质量诊断。它们的共同优点是灵活、不需要传统 GOP 的阈值体系；共同短板是分数稳定性和理由可信度——大模型给出的解释可能"听着有道理，但事实并不成立"。

TextPA 的消融很关键：LLM all-cues 0.643、独立 IPA match 0.653，外部分数融合后才到 0.728。也就是说 IPA 分支是「独立的匹配分再融合」，不是把更多 canonical 文本塞进 LLM prompt。

### 1.5 小结

把三类放在一起看：专用模型精度高但贵、设备泛化难；GOP 可解释但阈值和误报难调；LLM 直接判断灵活但分数和理由不够稳。现有研究还没有同时解决"便宜、泛化、可解释、说得对"这四个问题，这正是本课题要切入的地方。

## 2. 本地复现记录：TextPA 为什么达不到我们的要求

我们复现 TextPA，目的不是重复论文，而是判断它能不能直接用于上海高考听说练习。结论先说：TextPA 作为研究基线是成立的，但作为可落地的评测方案，它达不到我们的要求。这个判断既有公开数据上的依据，也在真实教学录音上得到了直接验证。

### 2.1 我们要什么，怎么验证

我们需要的不只是一个"大概打个分"的系统，而是：

1. 单条录音就能在线给分，不依赖整批数据校准；
2. 对真实教学录音稳定，不把好学生误报成有问题；
3. 能指出具体是哪个词、哪个音可能有问题，老师能复核；
4. 能处理未读完、设备差异、ASR 错词、词典缺词、长录音等真实情况；
5. 题目本身带明确的评分挡位，评分要能按挡位给分，分数分布不能挤在少数几档。

验证分三层：MultiPA 50 条公开样本（测能力上限）、SpeechOcean762 2,500 条测试集（测跨数据集表现）、真实教学作答包 12 段录音 / 11 个评分单元（测真实可用性）。环境为 Linux 8 核 CPU、7.7 GiB 内存、无 GPU；声学计算本地完成，大模型评分在线调用。

### 2.2 公开数据：最好也只能"粗排"

在 MultiPA 50 条样本上，我们实际调用 API 跑了几个模型，结果如下：

| 模型 | 准确度 PCC | 流利度 PCC | 融合后准确度 |
| --- | ---: | ---: | ---: |
| Sol high | 0.567 | 0.698 | 0.656 |
| Sol max（单次） | 0.626 | 0.725 | 0.697 |
| Luna max | 0.669 | 0.660 | 0.724 |
| DeepSeek max | 0.570 | 0.526 | 0.691 |

论文 GPT-4o-mini 的公开结果是 0.728，和我们最好的结果（Luna max 0.724）基本持平。这个量级的相关系数只能支持粗粒度排序，不能当考试分数。更关键的是，TextPA 的最终分数依赖整批测试数据做 min-max 归一化，换一条录音单独在线请求就没有同款分数——这一点直接不满足要求 1。

跨数据集也不乐观：TextPA 在 SpeechOcean762 上报告的准确度/流利度为 0.532/0.557（Gemini 口径），明显低于 MultiPA 上的 0.728；我们另外用一个大模型在该测试集上跑的一轮对照也只有 0.484。不同数据、不同模型组合下波动明显，离"稳定可用于评分"还有距离。

另一个常见问题是分数分布窄：零样本 LLM 打分容易挤在少数几档，公开实验里某次运行的 50 条样本有 49 条落在 2/3 两档，直到加入四极值锚点才把 Accuracy 的取值从 2 档扩到 17 档。对只有几档、且需要区分档位的评分场景来说，这种分布没有区分度。

### 2.3 真实教学录音：误报和分数翻转

公开数据只能说明"分数不高"，真实录音则暴露了更致命的问题。我们用按 TextPA 思路搭建的完整链路（ASR、声学模型、词典、LLM 评分），对一份真实作答包（12 段录音、11 个评分单元，上海高考题型）走完整流程，得到总分 8.25/10（当时的版本）。更重要的是：

- **好学生被误报**：一条高级教师近乎满分的朗读，系统只给 0.5/1；另一条教师朗读用旧声学模型被打到 81/100，还列出 8 个"重点复听"项。
- **同一录音，分数会翻转**：上面那条 0.5/1 的录音，音频和评分标准都没变，只把中间"纠错说明"的措辞从"断言问题"改成"保守描述"，分数就回到了 1/1。这说明分数受自然语言表述影响，不具备可复现性。
- **真实录音上模型会"听错"**：同一段 60 秒观点题，研究侧清晰率 96.7%，应用侧只有 46.2%；原因是声学模型把英语听成了带声调的中文音。换成英文 CMU 音素模型后升到 95.5%，12 段整体升到 90%–100%。
- **一个词典缺词就能让整题失败**：语音识别把 outweigh 听成 overweigh，词典没有这个词，旧逻辑直接抛错、整题无结果。

这些问题的共同点是：TextPA 这类"LLM 直接判断"的方案，给出的是句级分数和自由文本理由，既不能保证分数稳定，也不能保证理由有事实依据；遇到真实录音的设备差异、口音和工程边界，很容易失效。需要说明的是，这些证据来自我们按 TextPA 思路搭建的链路，不是论文作者的原始代码；但既然要落地到真实教学，这些问题就无法回避。

### 2.4 结论：TextPA 与我们的要求逐条对照

| 我们的要求 | TextPA 类方案的表现 | 真实证据 | 结论 |
| --- | --- | --- | --- |
| 单条在线给分 | 最终分数依赖整批 min-max 校准 | 论文口径只能批量；单条无同款分数 | 不满足 |
| 对好学生稳定 | 分数受 LLM 措辞影响 | 教师近满分朗读 0.5/1，改措辞后 1/1 | 不满足 |
| 能指出具体问题、可复核 | 只给句级分数 + 自由文本理由；理由可能不忠实 | 教师朗读被列 8 个"重点复听"；此前研究统计约四成判断"理由自洽但结论错误" | 不满足 |
| 分数要能区分挡位 | 零样本 LLM 分数常挤在少数几档 | 某次运行 50 条中 49 条落在 2/3 两档；四锚点实验才把取值从 2 档扩到 17 档 | 不满足（需外部校准） |
| 真实录音工程可用 | 对设备/声学模型敏感，缺词会崩 | 长段 46.2% vs 96.7%；outweigh 导致整题失败 | 不满足 |

而我们的题目本身有明确的评分挡位（rubric）：每个挡位对应可观察的评分标准。这意味着评分可以"先定挡、再在挡位内给分"，不需要让 LLM 自己发明一条分数刻度；从机制上就能避免上面这种"分数挤在少数几档"的问题，也便于老师复核。

因此，TextPA 适合作为研究基线和对照，不能作为本课题的最终方案。我们需要把"证据"和"评分"拆开：先用专用声学模型产出可核验的逐词/逐音素证据，再让大模型只做受约束的表述和按评分标准打分——这是后面方案设计的出发点。

| 阶段 | 参考/声学/LLM | 关键结果 | 结论 |
| --- | --- | --- | --- |

## 5. 未纳入本次收集

- **商业发音评估 API**（Azure Pronunciation Assessment、讯飞、ELSA 等）：未做实测与合规评估，不作为本轮选型依据。
- **MFA、WhisperX、ctc-segmentation、Kaldi GOP recipe**：仅作为潜在对齐/置信度改进方向记录，未做本地对照。
- **监督式发音模型**：缺少带音素标签的中国学生语料与训练预算，本轮不采用。
- **SpeechOcean762 训练**：仅用于离线指标对照，不用于产品训练或阈值标定。

## 6. 候选池结论

本轮可落地的组合收敛为三类：

1. **论文式零样本句级评分**（TextPA）——复现与 benchmark 用，不作为在线定级。
2. **开源声学证据链**（CMUdict + 英文 CMU-phone CTC + Viterbi/GOP）——产品发音诊断的核心。
3. **受约束的 LLM 表述**（证据整理 + rubric 评分两段式）——不替 LLM 猜测音素事实。

监督多粒度模型、商用 API 与复杂特征体系留作后续评估，不进入当前实现。各候选的详细清单见 [附录 A](appendix-related-details.md)。
