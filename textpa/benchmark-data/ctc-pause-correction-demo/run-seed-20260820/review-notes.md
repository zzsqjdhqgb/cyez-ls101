# 人工复核说明

`report.md` 保留 Agnes 的原始结构化输出，不代表这些结论已经由人工或独立声学模型确认。
脚本只严格校验 JSON 结构和 evidence ID 是否存在；LLM 是否忠实转述了 evidence 的内容，仍需语义复核。

## 已发现的语义风险

- 样本 1 的“未发现明显音素冲突”属于过度推断。提示词只包含排序后的最多 12 个候选，未出现候选不能证明该词正确。
- 样本 3 的 `apparently` 描述错写了 `P-W023-P03`：证据是 expected `/ɛ/`、observed `/ɪ/`，报告写成了 expected `/æ/`。
- 样本 3 的 `are` 把 `/ɚ/` 与 `/ɑːɹ/` 的差异直接当作错误，未充分考虑口音、重读和合法变体。
- 样本 3 将 `F-001`（1920-2190 ms）和 `F-002`（2700-3080 ms）相加为一个 650 ms 停顿；两段之间并不连续，不能直接合并成单一停顿强度。
- 样本 3 用“ASR 能产出连贯句子”推断整体可懂度尚可。ASR 文本只是输入数据，不能作为当前声学证据支持的正面结论。

## 复听时优先判断

1. 标出的音素冲突在人耳听来是否真实，还是 CTC 强制对齐造成的错位。
2. TextPA 的 `[SIL]` 时间段是自然句间停顿、换气，还是确实影响流利度的犹豫。
3. LLM 的中文解释和练习建议是否忠实于引用的 expected/observed phone，而非自行改写音素。

这些问题说明下一版应让确定性代码生成 finding，LLM 只负责组织措辞和练习建议，并显式禁止“没有候选等于发音正确”和跨事件合并停顿。
